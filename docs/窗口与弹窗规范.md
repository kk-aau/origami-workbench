# 窗口与弹窗规范

应用内窗口统一采用 `src/ui/dialog.css` 的森绿主题。颜色、圆角、标题栏、关闭按钮、输入边框、按钮、焦点和遮罩由这一份样式维护，同时覆盖浅色与深色。桌面确认窗也直接加载此文件。

| 场景 | 调用方式 | 内容组织 |
|---|---|---|
| 文件夹、重命名等短表单 | `AppDialog`，`size="small"` | 单列表单，取消在左，主要操作在右 |
| 帮助、显示与导出设置 | `AppDialog`，`medium` 或 `large` | 标题固定，内容区滚动，操作区按需固定 |
| 几何、曲面等工作窗口 | `TessDialog` 或 `AppDialog unwrapped` | 保留业务画布布局；工具栏、标题和控件共用标准 |
| 既有独立 HTML 窗口 | `ui-dialog` 类和 `openAppDialog()` | 保留专门尺寸及直接子级选择器，逐步复用公共 shell |
| 桌面同步确认 | `confirmAction(message)` | 返回布尔，取消及关闭均返回 `false` |
| 主进程关闭确认、关于 | `messages.confirm()` / `messages.info()` | 自有沙箱窗口、绑定主窗口，共享样式 |
| 启动等待 | `desktop/startupWindow.cjs` | 本地独立沙箱窗口，沿用公共颜色和字体；真实阶段、减少动态效果、超时／失败／退出；主窗口就绪后立即销毁 |

启动窗与便携版解压前画面的接力及验收见[启动过渡与等待反馈](启动过渡与等待反馈-20261018.md)。启动反馈不添加人为等待时间，不使用虚构进度百分比。

## 新窗口

```tsx
import {useId,useRef} from 'react';
import AppDialog from './AppDialog';

const formId=useId();
const input=useRef<HTMLInputElement>(null);

<AppDialog title="重命名折痕" size="small" onClose={onCancel}
  busy={saving} closeDisabled={saving} initialFocusRef={input}
  footer={<>
    <button type="button" className="ui-button" disabled={saving} onClick={onCancel}>取消</button>
    <button type="submit" form={formId} className="ui-button is-primary" disabled={saving||!name.trim()}>保存名称</button>
  </>}>
  <form id={formId} className="ui-dialog-form" onSubmit={submit}>
    <label>折痕名称<input ref={input} value={name} onChange={changeName}/></label>
  </form>
</AppDialog>
```

`AppDialog` 使用 HTML `<dialog>.showModal()`，提供真正的模态层、键盘焦点约束和嵌套窗口支持。它把窗口挂载到 `document.body`，避免被工作区隐藏或裁切。关闭时恢复触发控件的焦点；Escape 和关闭按钮走同一取消回调。执行必须完成的保存或迁移时，传入 `closeDisabled` 并禁用相应操作按钮。

公共样式在打印媒体下隐藏窗口，避免挂载到 `body` 的弹窗混入 CP 打印内容。

标题写具体任务。次要操作使用 `ui-button`，主要操作加 `is-primary`，不可逆删除加 `is-danger`。确认按钮写具体动作，普通提示不要增加不必要的确认步骤。短表单用 `initialFocusRef` 定位输入，破坏性确认默认焦点定位取消。长内容放正文区，底部操作区保持可见。

## 既有工作区兼容

复杂画布的业务 CSS 可能依赖 `:has(>.geometry-editor)` 等直接子级选择器。此时使用 `unwrapped`，或保留独立 `<dialog className="原业务类 ui-dialog">`，不额外包裹画布。

```tsx
import {openAppDialog} from './AppDialog';

useEffect(()=>{
  const restoreFocus=openAppDialog(dialog.current);
  return()=>{
    job.current?.cancel(); // 保留该工具自己的清理。
    restoreFocus();
  };
},[]);
```

公共样式只为新 shell 提供默认宽度；旧工具的宽高、布局和 SVG 坐标仍由该工具维护。纸张预览可保留白底；其上悬浮的工具和说明应有明确的表面色，避免深色主题出现浅字浅底。

## 桌面确认与信息

同步工程采用回调依赖 `boolean` 判断是否替换及关闭工具窗，不能直接换成 Promise。`confirmAction()` 继续使用同步桌面桥接；主进程打开独立沙箱 renderer 的自有模态窗，收到确认后才回复结果。取消、Escape、关闭、载入失败及主窗口销毁均拒绝操作，并恢复主窗口焦点。

主进程直接调用：

```js
await messages.confirm(window,{
  title:'删除模型',message:'删除后无法恢复，是否继续？',
  cancelLabel:'取消',confirmLabel:'删除模型',danger:true,
});
await messages.info(window,{title:'关于折纸工坊',message:version,detail:description});
```

桌面消息只通过 `textContent` 设置正文，窗口与 IPC 校验自己的发送方、主 frame 和本地资源；不允许 Node、外链导航或网页内容注入。关闭程序和重新载入分别处理，取消保留当前工程；批准一次重新载入不影响之后的关闭保护。

文件与目录选择使用现有系统选择器，以保留路径选择和权限行为。程序尚未启动成功时仍保留系统错误框作为兜底。浏览器版旧同步确认的安全回退保持原行为；新增页面表单和设置统一调用 `AppDialog`。
