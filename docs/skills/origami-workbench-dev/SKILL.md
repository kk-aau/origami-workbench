# 折纸工坊开发

## 工作入口

- 在当前工作区定位 `workbench-tauri/`，若已经位于该目录直接使用。本机通常为 `D:/codex/折纸工具/workbench-tauri`；路径迁移后以实际工作区为准，不另建同名项目。
- 读取根目录和迁移版 `AGENTS.md`，遵循其当前内容。`workbench/` 为只读历史对照；本 skill 不授权同步、构建或发布旧项目。
- 使用中文沟通。现有用户授权和最新明确要求优先于本 skill；本 skill 不额外增加确认流程，也不授权自动打包、联网发布或向他人发消息。
- 工具、依赖缓存和临时文件使用迁移版 `.toolchain/`，诊断输出使用 `.runtime/<任务>/`。用户工程在副本上复现；不修改原件、旧安装实例或已交付版本。

## 按任务取用资料

| 当前任务 | 读取内容 |
|---|---|
| 找入口、CP／折图／纸层／PDF 改动 | [代码地图与状态语义](references/architecture.md) |
| 报错、计算正确性、性能、旧问题复发 | [复现与历史保护](references/regressions.md)及迁移版 `docs/problems/INDEX.md` |
| 构建、打包、源码和许可交付 | [构建与交付](references/delivery.md)，再读项目当前打包规范 |

小改动只读取相关资料，不为普通文案、样式改动启动全项目审计或全量测试。

## 先判断问题属于哪一层

区分 CP 材料与折角、步骤操作意图、实际纸面姿态、层序约束与证书、画面显示。修改颜色和线型不应暗中改变折角；调整层序不应暗中改变三维顶点或 CP。先沿状态写入和计算调用链定位，再决定修改位置。

收到截图时，截图能证明现象，通常不能证明根因。先用现有工程、代码和日志推进；缺少复现所需数据时集中索取完整报错、应用版本、出错前工程与操作顺序。不要仅凭错误文案判断用户画错、拖坏纸面或数据已损坏。

## 每次问题都留下记录并对照历史

使用迁移版 `docs/problems/TEMPLATE.md` 在 `docs/problems/` 建立或追加问题记录，同步 `INDEX.md`。收到反馈先记已知触发条件、操作和实际结果；分析、修改、验证及交付过程中持续补充对应文件、因果链、解决方法和未决项。记录要求不等于另行授权修改或打包；只询问原因的任务也如实记录诊断范围。

理清当前问题的前因后果后、决定修复方案前，按错误文本、触发动作、状态变化、涉及文件和拟修改的保护机制检索旧问题、`docs/` 历史修复说明与回归测试。逐条记录关联类型、相同点、不同点、证据和旧案例验证结果。未找到同因记录时写明检索范围；证据不足写“待确认”，不能把未搜索写成“无关联”。根因变化后重新比对，完成后更新双向关联与回归结果。

同一根因的新发生追加事件，不覆盖过去的版本和触发结果；不同根因分别建档并互链。长期记录保留必要结论和最小复现，不能只指向可能清理的 `.runtime/` 日志。仍未复现、被取消、暂缓、无法修复的情况同样保留明确状态。不要把多个症状未经证据合并为一个已解决问题。

## 修改历史限制前

遇到容差、过滤、跳过、预算、分片、缓存失效或旧修复保护，先查注释、相邻测试、`docs/` 和可用的原始修复记录。若用户说明“以前故意这样处理”，把它作为需要验证的历史约束；不能直接断言现有行为是无意遗漏，也不能把未经证实的解释写成事实。

记录四件事：原限制保护的场景、本次失败的可复现输入、拟改变的边界、能检测旧问题复发的案例。保留“新失败案例修后通过”和“原受保护案例仍成立”两条证据。没有旧案例时明确该缺口，不以新工程通过或测试总数替代它。

不通过放宽精度、删除真实纸面、忽略矛盾关系或编造层序来消除报错。手动完整计算保持可取消且正常推进时不限时；自动预览的预算不得移植为手动计算上限。

## 实施与验证

- 先记录拟修改源码的原始 SHA256；把最小复现和结果放在独立 `.runtime/` 子目录。保留用户数据与代码变更的边界，不把完整私人工程加入测试目录。
- 对计算或状态行为改动，优先加入能在旧逻辑失败、修后通过的针对性回归，再运行受影响测试与必要的类型检查。测试应核对真实结果、关系、几何或持久化，不只匹配错误文案。
- 基础几何或层序修改需同时比较完整性与耗时；历史故障复核、浏览器验证、桌面实包验收分别记结果。用户明确跳过某项时遵守，并保留未执行说明。
- 独立读取可批量；同一工作目录中的依赖构建、源码冻结、打包不能互相抢写。Windows 上按实际退出码判断原生命令成功与否；stderr 的普通编译日志不等于失败。
- 汇报变更原因、验证范围、尚未解决的问题和交付状态。源码测试通过、能打开窗口、打包退出成功是不同结论。

## 维护本 skill

只有新的用户要求、可复现案例或可靠代码证据才更新规则。历史记录写明适用层、日期、证据位置及局限；本机 `.runtime/` 或旧 `output/` 可能缺失，缺失时不能当作已通过的验收。版本号、测试数量和工具路径均现场读取，不照抄旧交付。
