# 构建与交付

任何打包、发布整理或压缩／依赖配置调整前，读取迁移版 `docs/打包与体积控制要求.md`，采用第六节 Tauri 流程。不要复制本地旧脚本中的版本号和验收结果作为当前事实。

## 本地执行

- 工作目录必须是迁移版。使用 `scripts/toolchain-env.ps1` 配置 D 盘工具、缓存及临时目录；不复用旧 Electron 项目的可写依赖或数据。
- 从 `package.json`、npm 锁、Cargo、Tauri 配置、`src/app/state.ts` 读取基础版本；候选标识来自 `desktop-tauri/release.json`。同版不同内容不能静默覆盖已交付目录。
- 源码验证示例：`node_modules/.bin/tsx.cmd --test --test-concurrency=2 <实际相关测试文件>`、`node_modules/.bin/tsc.cmd --noEmit`。不要在 PowerShell 中向工具传入无法自行展开的路径通配符。
- `scripts/build-tauri.ps1` 默认包含前端类型检查与构建；检查其当前参数再调用。不要用旧 Electron 的 builder 命令代替。
- PowerShell 重定向原生命令 stderr 时可能把普通编译提示包装为 `NativeCommandError`。保留 stdout／stderr 日志，以进程退出码判断构建；不要因为调整日志捕获而吞掉真正的非零退出。
- 编译、源码归档、stage、打壳依赖同一冻结输入，依序执行。独立读取可以并发，不并行启动两套会写同一产物的构建。

## 用户明确要求“打包不检测”

这是该次交付的范围约定，不把它写成今后默认跳过所有检查。尊重明确的跳过要求，不额外运行单测、类型分析、独立引擎／实包检测或 GUI 验收。

仍执行生成可用产物所需的编译、资源整理、对应源码与许可交付、版本归档和哈希清单。打包脚本自带的输入完整性检查不应被伪造、删除或填写为已通过；失败就处理实际构建原因，不交付不完整附件。

如果常规入口捆绑了用户要求跳过的检测，可使用已理解的构建子命令，例如只执行 Vite 构建后用 `-SkipFrontend` 编译宿主。保留源码包和压缩参数，不能用删功能缩短等待。

交付状态写为“已打包，未执行本轮实包验收”，附真实未执行项。打包之前已完成的源码验证可以引用，明确不是对最终 EXE 的验收。不得沿用旧 GUI 结果或制造 finalize 所需的验收凭据。

## 正常发布与附件

按当前规范完成引擎复用依据、前端／图标／Rust Release、调试归档、冻结源码 ZIP 与 7z、stage、双 EXE、最终验收和 finalize。后端或依赖变更时不能无证据复用引擎。

应用包保留必要运行资源、完整许可与准确源码获取说明；源码 ZIP／7z、调试文件及清单独立交付。两类 EXE 使用同一运行输入，不在应用内塞入完整开发树或用户工程。系统 WebView2 前提应如实说明。

真实大工程的“导入／保存通过”不代替“正常关闭、重开同一记录和后续后台修订通过”。对源码、开发服务器、解包目录、最终安装版和最终便携版分别记录证据。

只对已生成的产物给出链接、实际字节数和版本。本地打包不等于网络发布；若未要求发布，不上传。
