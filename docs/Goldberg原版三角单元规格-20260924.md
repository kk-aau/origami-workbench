# Goldberg 原版三角单元规格对照

Origamica 15.0 笔记本 In[3322] (`GoldbergPatch[m,n]`) 对每个单元输出四元拼块规格 `{UnitTriangleTile, angles}, offset, rotation, scale`，不是只有三角网顶点。`UnitTriangleVertices` In[366] 定义了单位水平底边以及由前两个角确定的第三顶点。当前工作区的 `/api/tessellation/goldberg-reference` 数值参考现返回逐块 `tileSpecs`；点选弹窗中的三角面可查看角度、起点、旋转、缩放、扇区和原版单元序号。

设 `φ=π/m`，原版表中的 `i=1…n, j=1…i`。每个 `(i,j)` 先发出 A 型拼块，角度 `(2φ, π/2−φ, π/2−φ)`、起点 `(i−1)U(0)+2(j−1)sinφ U(π/2+φ)`、旋转 0、缩放 1；仅当 `i≠j` 时再发出 B 型，角度 `(π/2−φ, 2φ, π/2−φ)`、同一起点、旋转 `2φ`、缩放 1。`GoldbergTiling` In[3324] 将这组拼块依次转到 `m` 个扇区。`GoldbergOffsetTiling` 将上半部分旋转 180° 并平移 `(o,0)` 得到下半部分，且将下半部分的旋转值按 `Mod[rot+π,2π,-π]` 归一到 `[-π,π)`；现已按此保存角度，不能只靠三角形几何等价掩盖参数差异。数值参考与原版 `MakeOffsetGoldbergTiling` 线图使用同一居中坐标系，因此整体再平移 `(-o/2,0)`；响应中的 `tileFrameTranslation` 明示这个坐标变换。

对照结果：`GoldbergPatch[7,2]` 的四块顺序为 A、A、B、A；第 3 块角度 `(5π/14, 2π/7, 5π/14)`、起点 `(1,0)`、旋转 `2π/7`。分别用拼块规格反算三角形顶点，`m=3,7,8,12` 多组单扇区及整片网格的每个三角面集合完全匹配；`m=8,n=2,o=0,1,3,4,5` 和 `m=6,n=3,o=6` 的每条拼块边都属于原版偏移线段集合，包括 `o≥2n` 的分离参考几何。专项后端 17 项、HTTP 路由 1 项、`npm run build` 通过。1000×720 真实浏览器复核第 3 块点选、键盘切换、偏移线图点选及弹窗无滚动；图见 `output/playwright/goldberg-tile-specs.png`。另复核 `m=8,n=2,o=5` 下半片第 17 块原版规范化旋转 `−π`，见 `output/playwright/goldberg-offset-tilespecs.png`。曾发现 SVG 的焦点轮廓在 Chrome 被放大成黑色覆盖，已改由选中三角形的青色边与填充表示焦点，重新截图正常。

`tileSpecs` 以整数分数保存每个角和旋转相对 `π` 的精确值，并给出用于绘图的数值顶点。尚未提供 Mathematica 的符号表达式对象，也不实现 `Simplification`/`Numeric` 选项对符号返回值的区分。没有 Wolfram 运行环境，逐点比较是对笔记本公式的独立代数实现与当前网格的交叉检验，不能称为原版解释器输出验收。`o≥2n` 的拼块和线图只是参考几何，仍不可作为一张连续纸的折痕／平折结果采用。

## 非整数拼块偏移与线图的区分

继续复核 In[3326] `GoldbergOffsetTiling[m,n,o]`：`o` 只出现在下半片拼块的水平平移 `(o,0)` 中，函数没有整数或正数检查；In[3327] 使用 `o=1` 作图，但笔记本未保存可提取的 `Out` 数值列表。与它不同，In[3368] `MakeOffsetGoldbergTiling` 需要按 `o` 枚举单位桥接线，因此工作区仍要求线图／可采用 CP 的 `o` 为非负整数。

新增独立“拼块排布”参考模式，在偶数阶允许有限实数 `−64≤o≤64`，奇数阶完整 `GoldbergTiling` 固定 `o=0`。它从原版 UnitTriangleTile 规格直接绘制按顺序排列的三角面，不添加桥接线、外心对偶、山谷赋型或平折结论。对于 `m=8,n=2,o=1/2`，居中坐标系的第一块顶点为 `(-1/4,0),(3/4,0),(√2/2−1/4,√2/2)`；第 17 块为 `(1/4,0),(-3/4,0),(1/4−√2/2,-√2/2)`，旋转值为原版规范化的 `−π`。独立代数锚点与 32 块返回值误差 < `10⁻¹²`；`o=−3/4` 的上下起点分别为 `3/8`、`−3/8`。整数 `o=1` 时，拼块排布与偏移线图的拼块规格和边集合完全一致；偏移线图仍拒绝 `o=1/2`，两类参考互不串用。Goldberg 后端 18 项、Goldberg+advanced 31 项、HTTP 专项、构建和 1000×720 浏览器小数／负数输入、切回整数线图与无滚动检查均通过；截图 `output/playwright/goldberg-fractional-tile-offset.png`。

该模式仍只有有限数值拼块列表。原版无界的 Mathematica 符号 `o`、`Simplification`/`Numeric` 返回类型及真实 Wolfram 求值输出尚未复现；也未证明任意实数偏移下拼块是单张可平折纸面。

## 有序线段列表与原版输出边界

复核笔记本 242946–243324、246220–247306 行：GoldbergPatch、GoldbergTiling、GoldbergOffsetTiling、MakeGoldbergTiling 与 MakeOffsetGoldbergTiling 的保存样例只有 `In` 构造和绘图调用，没有可提取的 `Out`／`Print` 数值列表。跨 `m/n/o` 的公式重算可验证实现与原始算法一致，却不能称为与 Wolfram 保存输出逐点比对。

原版 `MakeGoldbergTiling` In[3359] 的线段输出有顺序：先全体径向边，再全体横向边，最后全体斜向边；每一类内按扇区、横向索引、径向索引排序，并保留每段的起终点方向。`MakeOffsetGoldbergTiling` In[3368] 对上述列表用端点 `y<−10⁻⁶` 将上、下半部分组，分别平移 `−o/2`、`+o/2`，最后附加 `o` 条正向桥接边。工作区原先把三类边在每个扇区内交织，偏移时也未先分组；边的无序集合正确，但有序列表不等价。现在参考线图返回原版分组与方向。`o=0` 返回未偏移的 `MakeGoldbergTiling` 列表及其正确来源名，奇数阶也适用；`o>0` 返回 `MakeOffsetGoldbergTiling` 列表。独立按径向单位向量插值的测试对 `m/n/o=(5,2,0),(7,3,0),(6,1,1),(8,2,1),(8,2,3),(8,2,5),(6,3,6)` 逐项比较起终点和位置。

项目 `.venv` 下 Goldberg 专项 19 项通过。该核对只确认原版源代码的有限数值线段语义。真实 Wolfram 求值输出、符号类型及 `o≥2n` 的连续纸面／平折仍没有等价证据。

## 零偏移时两种原版函数的不同旋转元数据（2026-09-27）

原版 In[3324] `GoldbergTiling[m,n]` 与 In[3326] `GoldbergOffsetTiling[m,n,0]` 绘出的三角形重合，但不是相同的拼块规格列表。后者即使 `o=0`，仍把上半片旋转 `π` 复制为下半片，并对下半片每个旋转角执行 `Mod[rot+π,2π,-π]`。此前只读参考查询把零偏移固定解释为 `GoldbergTiling`，因而无法读到 `GoldbergOffsetTiling[...,0]` 的角度元数据。

现在“拼块排布”可明确选择原版函数。`sourceVariant=full` 查询 `GoldbergTiling`，只接受 `o=0`；`sourceVariant=offset` 查询偶数阶 `GoldbergOffsetTiling`，接受有限实数偏移（包括零）。不带新参数时仍沿用既有行为：零偏移取完整排布，非零偏移取偏置排布。两者都只返回参考几何，不进入 CP／FF 采用流程。以 `m=8,n=2,o=0` 为例，第 17 块在完整排布的旋转为 `π`，偏置排布为 `−π`，顶点在数值误差 `10⁻¹²` 内相同。

新增独立源式回归覆盖 `(m,n)=(6,1),(8,2),(10,3)` 的全体 `m·n²` 拼块次序、角度与零偏移元数据，并对 `o=−3/4,1/2,1` 核对上下平移及顶点。这里的“独立”指测试用笔记本 In[3324]/In[3326] 的有序循环和角度公式重算；保存笔记本没有这些调用的可机读 `Out` 或 `Print` 数值，因此不能称为 Wolfram 求值输出对照。原版 `Simplification`/`Numeric` 的符号返回类型仍未实现。

1000×720 真实浏览器在最终构建 `main-Cngki6Sr.js` 下选择 `m=8,n=2,o=0`：`GoldbergOffsetTiling` 的第 17 块显示旋转 `−π`，切到 `GoldbergTiling` 后同一块显示 `π`；两个模式都显示 32 块，不修改当前折痕。参考弹窗 625/625、页面 720/720，无垂直滚动。验收时发现原版函数下拉仅 95 px 宽，名称截断；已扩展到所在栏宽度。
