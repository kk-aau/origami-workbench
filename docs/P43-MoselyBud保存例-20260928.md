# Origamica 第 43 节：Mosely Bud 保存例 In[3481]/In[3482]

原版只读笔记本 `tmp/Origamica-15.0-reference.nb` 第 259745–259886 行定义 `MoselyBudCrossSectionPt[r]`；第 264454–264654 行的 In[3481]/In[3482] 都取 `r=0,1/20,…,1` 的 21 个 `Re[N[...]]` 点，逐点乘 `{1,-1}` 得下垂剖面。两例调用原版 `MakeRadialPot` 的默认 `PotPlanar`、`m=4`、`TypeMinimumAngle=30°`，`ρ` 分别是 `0` 和 `.3333`。后者原注释称 propeller Bud。原保存单元是图形调用，没有可机读的 Wolfram 顶点 `Out`。

原剖面高度的内点以复数不完全椭圆积分表示，端点另有完全椭圆积分分支。其**保存的实数分支**在 `0≤r≤1` 可稳定改写为

`x(r)=(√(1+4r−4r²)−1)/2`，`z(r)=∫₀ʳ √(8t(1−t)/(1+4t−4t²)) dt`。

等价推导需固定原复式的主值分支。令 `φ(r)=ArcSin[(√2−1)√(r/(r−1))]`、`M=17+12√2`，在 `0<r<1` 对原式求导，使用 `∂F(φ|M)/∂φ=1/√(1−M sin²φ)`、`∂E(φ|M)/∂φ=√(1−M sin²φ)`，并按原式取实部整理，得到 `z'(r)=√(8r(1−r)/(1+4r−4r²))`。原式的 `r=0` 特殊分支给 `z(0)=0`，所以微积分基本定理给出上述实积分；`r=1` 的特殊完全椭圆积分分支等于该积分的连续极限。另一方面 `x'(r)=(1−2r)/√(1+4r−4r²)`，故 `x'²+z'²=1`，与原版将 `r` 定义为曲面弧长相符。代换 `r=sin²u` 后，被积式变成 `√2 sin²(2u)/√(1+sin²(2u))`，在两端光滑；`z(1)=0.8472130847939791`，再用 `z(1−r)=z(1)−z(r)` 避免近端损失。`backend/tessellation_mosely_bud.py` 和 `src/app/radialPotMoselyBudSaved.ts` 各自以 512 等分 Simpson 积分实现有限数值点列；运行时没有复数/椭圆积分依赖。`output/experiments/p43_mosely_bud_branch_probe.py` 以 50 位精度将原 `EllipticK/E/F` 主支逐项写出：39 个内点的复式数值导数与上式最大差 `2.31×10⁻⁴⁹`，七个高精度剖面锚点及特殊端点也与实积分一致。正式 Python/TS 专项检查这些锚点、21 点跨语言误差 `<2×10⁻¹¹`、端点、双保存例与非法实数域。

工作区“镶嵌设计 → 空间构造 → 旋转对称壶体”已提供两个原版 Mosely Bud 一键输入。径向壶体剖面容量从 12 点扩到 24 点，同时保留 `5×m×(点数−1)≤600` 的面预算、非有限/非单调/退化点拒绝和旧 12 点行为。两个保存例各得到 **393 顶点／792 边／400 面**；真实后端二维几何、逐面所有顶点对二维/三维距离及三维共面通过，静态等距误差小于 `10⁻¹⁰`。前端把受验三维坐标送入独立等距门禁，可采用独立展开折痕工程副本；篡改三维顶点后会拒绝，工程 JSON 参数及来源严格读回。

1000×720 Chrome 实际从空间构造选择 In[3481] 与 In[3482]，两次 21 点请求均 HTTP 200，显示 792 边、400 面，采用按钮可用，计算已空闲；二维/三维和背面切换正常。侧栏、画布、底栏均无纵向或横向滚动，浏览器没有运行时错误。布局与响应记录在 `output/playwright/mosely-bud-browser-report.json`，截图为 `mosely-bud-in3481/3482-1000x720.png` 和对应 `-spatial` 图。
