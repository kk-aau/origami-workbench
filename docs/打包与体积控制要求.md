# 打包与体积控制要求

生效日期：2026-10-18。依据 v0.13.26、v0.13.27 的实包核验结果制定，适用于后续 Windows x64 安装版、便携版及其发布附件。

本文件是当前执行规范，历史记录用于追溯。日常开发只改源码并按需构建、测试；用户要求打包时，必须执行完整流程。本文不构成自动打包或对外发布授权。

2026-10-28 用户确认：后续开发与打包均以 `workbench-tauri/` 为默认主项目。本文第六节的 Tauri 流程优先适用；前五节的通用质量要求继续执行，其中 Electron 命令、`workbench/` 工作目录及旧版体积数据仅作历史对照，不作为当前操作入口。

2026-10-26 用户更新：本迁移工程后续应用包不再内嵌完整源码。应用与同版本完整源码附件分别交付，在全部功能、离线计算、正确性与性能不退步的前提下尽量缩小体积。该更新优先于历史“源码必须随应用内嵌”的要求；原 `workbench/` 保持只读。

## 一、必须保留的方案

| 项目 | 强制要求 |
|---|---|
| 功能与数据 | 保留现有编辑、导入导出、平折、三维、工作日志、取消和关闭保护；完整计算在本机离线执行。不得删功能、改用预生成结果或依赖用户另装运行环境来换取体积下降 |
| 前端依赖去重 | `react`、`react-dom`、`earcut`、`fast-xml-parser`、`fflate`、`rabbit-ear` 已由 Vite 打入前端，放在 `devDependencies`；当前桌面服务仅用 Node/Electron 内置与本地模块，`app.asar` 不再复制 `node_modules`。引入真实运行时外部依赖前须重新核对打包和实际调用，不能机械移入开发依赖 |
| 语言 | `electronLanguages: [zh-CN, en-US]`；最终运行目录只保留这两种语言包 |
| 调试能力 | Vite 继续生成 sourcemap；运行包排除所有 `.map`，另存 `build/debug/zhezhi-debug-<版本>.zip` 及版本清单，逐项核对 map 和生成资源的 SHA256 |
| 启动反馈 | `package:icon` 生成 `build/icons/startup.bmp`，由 `portable.splashImage` 在解压前显示；运行包必须包含启动窗口控制器、preload、HTML/CSS/JS 及共享样式。Electron 显示真实启动阶段，主窗口准备好后立即切换，不人为等动画、不伪造百分比；失败／退出及减少动态效果须可用 |
| 计算引擎 | 默认使用已验证的 Python 几何路径；当前生产构建排除 `numba`、`llvmlite`、`matplotlib`、`PIL`，并保留原有 `tkinter`、`IPython` 排除项。开发环境可显式启用 JIT，不能因此恢复生产包的 LLVM／绘图依赖。不得继续盲删 SciPy、NumPy、Cairo 或求解器组件 |
| 对应源码 | 同一份完整源码清单同时生成常规 ZIP 与 solid 7z，解压后的路径、文件数量及逐文件 SHA256 必须一致，并对应本次冻结源码。文件数量随项目增长，不固定为历史的 4,858 个 |
| 源码独立交付 | 应用内禁止放完整源码归档、开发源码树、源码清单和源码构建记录。完整对应源码 ZIP 与 solid 7z 作为同版本独立附件，与应用同位置、以等价方式提供。应用只保留必要运行资源、许可与 `resources/legal/SOURCE-AVAILABILITY.json/.txt`，其中附件名称、字节数与 SHA256 必须准确 |
| 源码压缩参数 | 当前 7z 使用 `-t7z -mx=9 -md=64m -ms=on -mtc=off -mtm=off -mta=off`；ZIP 保持常规 Deflate 和 UTF-8 文件名，不用 Windows 常规 ZIP 工具不能正常读取的压缩方法替代 |
| 安装包压缩 | 保留 `nsis.differentialPackage: false`；当前没有自动差分升级，避免恢复其非 solid 布局。最终 EXE 内嵌归档应实测为 solid、主 LZMA2 字典 64 MiB。字典大小依赖当前锁定 builder 的行为，不能只看 YAML 就假定符合 |
| 许可与来源 | 保留项目 LICENSE、第三方声明、Electron／Chromium 声明、前端已捆绑依赖及其传递依赖的许可／包信息、Python 许可和构建材料。包移入开发依赖不代表它的许可可以删除；没有独立 LICENSE 的组件保留其包信息及相应 README 说明 |
| 依赖版本 | 按 npm 与 Python 锁文件构建。打包瘦身不能顺便升级依赖或修改数值算法；工具链或依赖变更须单独说明并验证 |
| 工程隔离 | 排除用户工程、profile、恢复稿、操作日志、私有数据、`.venv`、测试输出及构建缓存。验收使用独立数据目录和临时端口；不得关闭用户正在使用的旧实例或清理其数据 |

## 二、每次打包的执行顺序

本节表中命令记录原 Electron 的执行顺序，其历史工作目录为 `workbench/`；当前迁移版工作目录为 `workbench-tauri/`，命令和流程按第六节替换。逐步检查退出码；PowerShell 下检查 `$LASTEXITCODE`，任一步非零立即停止，不继续制作或交付后续产物。

| 顺序 | 必做事项与入口 | 完成条件 |
|---|---|---|
| 1 | 核对范围、版本及旧产物 | `package.json`、`package-lock.json` 根版本和 `src/app/state.ts` 中的 VERSION 一致；记录基线体积，保留旧 EXE、版本化源码、SHA 清单和引擎文件清单；不制造未实际发布的下载链接 |
| 2 | 准备工具与适用测试 | 按锁文件准备 npm、Python 构建依赖，记录实际 Node/Electron/builder/Python/PyInstaller 版本；完成受改动影响的测试并记录已有失败，不能把未执行项目写成通过 |
| 3 | 构建或复用引擎 | 后端、vendor、依赖锁、构建脚本或构建参数变化时执行 `npm run package:tess`；满足下节条件才可复用旧引擎 |
| 4 | 构建前端与图标 | `npm run build`、`npm run package:icon` 成功；确认版本、图标及本地资源正确 |
| 5 | 保存独立调试材料 | `npm run package:debug`；map 与对应生成资源的 SHA256 一致，归档带版本 |
| 6 | 冻结源码并生成双归档 | 在本次全部源码、说明和版本修改完成后运行 `npm run package:source`；核对 ZIP／7z 内容、许可和 BUILD-INFO。此后若再改相关源文件，重新执行受影响的构建、debug 和源码归档步骤 |
| 7 | 组装双 EXE | 使用下方本地 Electron 命令；安装版与便携版来自同一冻结输入，构建成功后再进行下一步 |
| 8 | 整理发布附件 | `node scripts/finalize-release.mjs` 复制对应源码、使用说明并生成当前通用 SHA256 清单；随后完成下节要求的版本化归档 |
| 9 | 实包核验与真实应用验收 | 必须完成第四节；仅验证开发服务器或 `win-unpacked` 不足以证明最终 Portable 可用 |
| 10 | 交付与收尾 | 输出体积对比、变更和验收边界、产物路径及 SHA256；清理自己的测试实例／端口及可再生成的试验副本，保留证据和已交付文件 |

当前已验证的离线组装命令为：

```powershell
.\node_modules\.bin\electron-builder.cmd --config desktop/electron-builder.yml --win --x64 --publish never --config.electronDist=node_modules/electron/dist
```

`npm run package:desktop` 当前会依次执行前端、引擎、图标、debug、源码和 builder；它总会重建引擎，且**尚未自动执行 finalize、版本化源码保留及完整验收**，也未默认传入上面的离线／禁止发布参数。它成功后仍须补齐本规范要求。验收脚本目前主要保存在 `output/`，并非已统一接入 npm 的自动发布门禁。

## 三、引擎复用、性能与版本归档

| 项目 | 必须执行 |
|---|---|
| 复用前提 | 确认相关后端与 vendor 源码、依赖锁、工具版本和构建参数未变；完整比较引擎目录的相对路径、文件数量、大小及 SHA256，不能只比较 EXE。记录来源版本、源码依据、清单和复用目标版本；证据不足时重建并验证 |
| 引擎改动 | 与旧版真实引擎使用相同输入矩阵、预热／轮数、机器条件及统计口径，核对几何、拓扑、山谷线型、折角、检查、警告和错误。数值比较精度和忽略字段须明确记录 |
| 性能门槛 | 同一口径复核典型及慢请求。出现可复现的性能或正确性退步时撤回候选；不能换统计口径掩盖退化。压缩后的启动／解压也要实测，不能只报告文件变小 |
| 旧版本保留 | 保留上一版 EXE、源码、SHA 清单及验收证据。通用名可以指向当前版本，但必须额外保存 `Zhezhi-Workbench-<版本>-Source.zip`、`Zhezhi-Workbench-<版本>-Source.7z`、`SHA256SUMS-<版本>.txt`，避免下次覆盖后失去对应关系 |
| 版本化 SHA | 版本化清单至少覆盖当前 Setup、Portable、版本化 Source ZIP 和 7z 四个文件，并使用实际交付文件名。独立 debug 归档及其清单也要留存 SHA256；与版本一同归档但不嵌入应用 |
| 同名产物 | 不静默覆盖已交付同版本的不同内容；发现同名内容不一致，先核对来源并使用明确的新版本／候选位置整理 |

v0.13.27 已撤回一项只节省少量空间、却在曲面 ODE 请求中连续测得耗时增加的引擎候选。最终引擎与 v0.13.26 的 195 个文件逐字节一致。后续不得把那份候选的性能数据当成已交付引擎的结果，也不得未经验证重新纳入。

## 四、发布前必须通过的检查

| 检查对象 | 验收要求 |
|---|---|
| 实包资源 | 检查 `app.asar` 的版本、当前源码／前端资源、重复依赖、`.map` 排除及中英文语言包；确认离线资源完整，独立 debug 归档没有混入应用 |
| 源码与许可 | 独立 ZIP／7z 解压后的逐文件 SHA256 与冻结源码一致；应用内源码归档数量必须为零。原始许可证、归属及必要包信息保留；源码的 BUILD-INFO、完整清单与重建材料在源码附件中。实际双 EXE 解压后的源码获取说明须与外发附件名称、版本、字节数、SHA256逐项匹配 |
| 最终计算引擎 | 打包后的完整引擎目录与已验证的 build 引擎逐文件一致；核查排除模块，包括 PyInstaller 内部 PYZ 中的模块，不只看目录名 |
| EXE 内嵌归档 | 校验 Setup 与 Portable 的实际内嵌 7z 头、声明范围与 CRC；核对 payload 一致、solid／64 MiB 主字典、文件数量与解码总字节数。不能只按签名位置猜测偏移，也不能用试验归档的结果替代最终 EXE |
| 桌面生命周期与日志 | 验证独立 profile／工程库、renderer sandbox、授权日志读取、真实日志下载、普通关闭、未保存取消／确认、最后关闭日志落盘。不得使用 renderer `window.close()` 替代原生 `BrowserWindow.close()` 关闭路径的事件验证 |
| 文件与计算 | 实际验证 CP／FOLD 的 CR、LF、CRLF 和带 BOM 的 UTF-16、非法输入、超限提示、取消及迟到结果保护；失败保留当前工程。验证 OPX 中文实体与几何、平折多面层序、真实三维后端运行 |
| 真正的 Portable | 必须直接启动最终单文件 EXE，确认解压前启动图、Electron 启动画面接力、实际 TEMP 解压、本次版本、独立数据、真实服务、主界面及普通关闭；核对 Electron 与外层启动器退出码、日志落盘和所有测试端口释放。新增启动反馈须另验慢启动提示、失败／取消及减少动态效果，详见[启动过渡与等待反馈](启动过渡与等待反馈-20261018.md) |
| 测试环境 | 不操作用户实例，不自动点击系统按钮；可用隔离的本机调试接口驱动同一应用路径。受执行沙箱限制的失败要保留证据并在正常桌面权限下隔离复核；不能关闭 renderer sandbox 或加 `disable-gpu` 来把实际故障隐藏成通过 |
| 体积与结论 | 分别记录两种 EXE、解包总量、Electron、引擎、应用和源码资源的字节数，按 MiB 比较同口径基线。任何增长须解释来源；无解释的重复依赖／映射／重复源码回流不能交付。明确本轮执行、沿用和未执行的检查及已知失败 |

只在相同引擎文件及相关源码／依赖确实未变时沿用完整引擎回归证据，并明确“本轮未重跑”。不能沿用旧 GUI 验收来代替新版实包验收。测试数量随版本变化，不以历史数量冒充本轮结果。

以下为 v0.13.27 的实际交付基线，用于识别回流；不是未来所有版本不得增长的硬上限。应用新增必要功能或工具链更新引起的增长须解释并验证。

## 六、独立 Tauri 版补充（2026-10-26）

用户已明确选择 Tauri＋系统 WebView2、Rust 替代 Node 服务，并要求在新目录迁移且不改原工作区。本节只适用于 `workbench-tauri/`，原 `workbench/` 保持只读。前五节关于完整功能、离线引擎、对应源码、许可、调试、冻结、实包验收和版本归档的要求继续执行；Electron 专用的 asar、语言包、preload 和 builder 命令按下表替换。

| 项目 | Tauri 版执行要求 |
|---|---|
| 架构边界 | 不分发 Electron／Node；复用系统已有 WebView2，不自动下载或安装运行环境。使用说明必须写明此前提，不能宣称在无 WebView2 的系统上可直接运行。缺失时明确提示；完整 Python 离线计算不裁剪 |
| 版本隔离 | 前端、npm锁、Cargo和Tauri版本一致；候选标识取 `desktop-tauri/release.json`，文件名包含 `Tauri` 与候选标识，不能覆盖原版同版本产物 |
| 工具和数据 | npm／Cargo／pip、MSVC、SDK、NSIS及临时构建目录均在D盘；安装默认D盘，便携解压优先D盘，数据独立保存；后续四区需求在本迁移版 `src/`、`public/`、`simulator/` 中实现，原 `workbench/` 保持只读 |
| 宿主资源 | EXE相对定位 `resources/dist`、`resources/engine`，不使用构建机源码绝对路径；运行包无 `.map`、PDB、node_modules、用户数据、工具链、完整源码归档或开发源码树；用于实际运行的打包JavaScript、Python资源及引擎归档不得按扩展名误删 |
| 构建和调试 | 按锁文件构建前端、图标和Rust Release；`scripts/package-tauri-debug.mjs`归档sourcemap和PDB，记录各生成文件、符号及EXE的SHA256 |
| 对应源码 | `scripts/package-tauri-source.mjs`使用同一冻结清单生成普通ZIP与solid7z，包含宿主、前端、Python/vendor、NSIS脚本、锁定Rust依赖完整源码和许可；双归档实际解压后逐文件校验 |
| 应用／源码分离 | Source ZIP／7z 与 Setup／Portable 同版本独立交付，应用保留 `resources/legal` 完整原始许可及小型源码获取说明，不复制源码归档、巨大源码文件清单或源构建记录；发布入口须同时提供对应源码，不能虚构下载地址，也不能用“以后再补”替代本次交付 |
| 自动门禁 | stage拒绝源码混入；最终EXE解包核验再次拒绝源码归档与开发目录；finalize必须核对独立源码双归档、应用中引用的名称/字节数/SHA以及完整许可集合。缺失或不匹配时禁止交付 |
| 外壳与压缩 | NSIS安装版和便携版原样内嵌同一个solid LZMA2 64MiB的payload.7z，不再对其二次压缩；最终EXE内实际7z头、范围、CRC和完整归档SHA均须核验。外层NSIS自身使用其CRC，不能将其误报为7z压缩 |
| 安装／卸载 | 独立名称及HKCU注册项；安装目录可选；升级和卸载不得影响运行中的原版。卸载仅移除明确的应用文件清单，不递归删除用户数据 |
| 便携启动 | 解压前显示应用图，运行宿主真实启动页；唯一临时目录经绝对路径和自有标记核验后才能清理，等待宿主结束并保留数据；不得直接以解包目录验收替代最终单EXE |
| 最终验收 | `verify-tauri-engine.py`核对全引擎与PYZ；`verify-tauri-bundles.py`验双EXE与payload；`verify-tauri-packaged-gui.cjs`通过生产路径验导入／取消／平折／WebGL2／折序PDF／日志；真实原生WM_CLOSE及取消确认需单独记录 |
| 大工程保存与重开 | 大工程相关改动必须在最终实包验证完整导入、保存后正常关闭、重新打开同一保存记录及两轮实际后台修订请求；逐项核对几何完整性，并记录界面最长响应空档、进程树内存和CPU进展。导入／保存通过不能替代重开通过；不得把ResourceTiming中同URL的POST误当GET，也不能仅延长测试超时掩盖真实长忙或内存保护触发 |
