### 阶段分别在做什么

| 阶段 | 工作内容 |
|---|---|
| 读取 / 查缓存 / JSON | Worker 读取 File 文本、计算文件摘要并查询本机验证收据、解析对象。不是分别读取三遍磁盘 |
| 校验工程及几何 | 检查工程结构、步骤关系和几何有效性；仅改说明而失去整文件收据时，仍保留这项完整校验 |
| 当前步 / 姿态和纸层 | 按前序纸面关系恢复快照与空间接触关系；新路径查输入完全一致的姿态结果。当前步完成时额外生成只读纸面预览 |
| 完成缓存写入 | 等待已发出的压缩缓存写入收尾；压缩、网络与写盘的大部分工作已和恢复重叠 |
| 整理 CP | 统一各步骤前后 CP 与工程状态对应，避免陈旧快照误用 |
| 恢复画布折痕 | 验证保存绘图是否匹配，补齐需要恢复的已有折痕；不是跳过绘图准备 |
| 更新本机缓存 | 核对完整文件输出，满足条件才写入整文件验证收据，或保存完整接触结果序列 |
| 准备入库数据 | Worker 编码完整工程为不可变 Blob，供后续暂存复用；这时尚未写入文档库 |
| 分批传输 | 带顺序与确认的完整工程分块传给主线程；收到全部数据后才发布为编辑工程 |

## 实现及代价

| 项目 | 行为与边界 |
|---|---|
| 姿态复用 | 键包含完整姿态输入、前序纸面依据、计算代码版本；说明改变不再迫使所有姿态重算。几何/纸层/前序变化会重新算受影响姿态 |
| 算法更新 | 构建时指纹覆盖导入 Worker 的相对依赖、嵌套 Worker、vendor、锁文件和构建配置。本次扫描 338 个输入，包含 14 个 vendor 文件。相关算法变化失效；图外纯界面变化不主动失效 |
| 磁盘空间 | 本案例 111 个缓存文件合计 6,652,513 字节（6.34 MiB）。复用原有缓存池，总上限 64 MiB、单文件上限 8 MiB；淘汰只影响速度 |
| 内存 | 最多四个不可变姿态快照并行压缩/写入；不额外复制整份工程。峰值内存本轮未实测，不承诺减少内存占用 |
| 当前步预览 | 通过现有绘图器生成纸面 SVG；只读、可缩放。完整校验与 CP/折痕整理完成后才替换编辑工程、保存、允许导出 |
| 回退 | 缺失、损坏、不兼容缓存按原计算路径恢复；缓存不能使有效工程打不开，不能放过源工程结构/几何校验 |
| 取消 | 在实际 UI 出现预览后点击取消，22 ms 关闭；无半成品工程发布，预览清除。Worker 停止，已完成的正确缓存可保留 |
| 文件格式 | 保持 zds 格式及原件不变，不要求转换文件；首次在另一台电脑打开仍需建立本地缓存 |
| 首次成本 | Worker 测得多 2.607 s；GUI 另轮多 0.980 s。冷开全流程没有变快，提升主要在早期预览与之后的重开 |
