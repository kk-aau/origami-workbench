# Origamica 第 36 节：单位正多边形偏置扭转具名拼块（2026-09-24）

原笔记本 `tmp/Origamica-15.0-reference.nb` 的 `UnitRegularPolygonCenter`（26212–26224 行，In[428]）为 `(1/2, cot(π/n)/2)`；`UnitRegularPolygonVertex`（26352–26373 行，In[433]）逐点围绕它旋转，使首边为 `(0,0)→(1,0)`；`UnitRegularPolygonVertices`（26388–26402 行，In[434]）汇总这些顶点。稳定具名型 `{UnitRegularPolygonOffsetTwistTile,n,w,d,types}` 在 224687–224770 行定义，`RenderTile` 的 In[3018]（224815–224834 行）将其直接交给 `PolygonOffsetTwistTile[UnitRegularPolygonVertices[n],w,d,types]`。通用偏置拼块的 In[2919]（215823–215842 行）指定垂直褶线 `π/2`，仅 `d>0` 时使用逆时针赋型。因此 `d` 是沿边中点的**有符号偏移**；具名说明文字 224722–224729 行称它为“pleat angle”与实际委托参数不符。

保存 In[3019]（224841–224906 行）给 `n=4,w=.2,d=.15,types1=types2=VVVV`，第二块用 `d=-.15`、平移 `{0,1}`，并调用 `EmbedTiling` 绘 Tiling、CreasePattern、FoldedForm2D。此处没有保存可供数值对照的 Wolfram 点、边、面表或独立数值 Out。因此 [具名后端](../backend/tessellation_unit_regular_offset.py) 复现的是源码参数和委托关系所确定的构造，不声称生成图元与原绘图逐点相同。该模块保留 `tileType`、边数、宽度、偏移和逐边中心 `M/V`，使用已验证的单位顶点和有向褶线交点构造器；输入限在现有构造器可处理的凸 `3–12` 边、`0.05≤w≤0.8`、边界内偏移及非退化交点子域。范围限制是本项目约束，不冒充原 Wolfram 函数的报错行为。

相邻角度辅助 In[3012]（224441–224457 行）印出 `Mod[ArcTan[w/(2d),cot(π/n)],π]`，而其反函数 In[3013]（224482–224493 行）给 `d=(w/2)cot(π/n)cot α`。在保存例的 `n=4,w=.2,d=.15` 上，打印的双参数顺序得 `56.309932474°`，反函数的几何分支则得 `α=atan2(w cot(π/n),2d)=33.690067526°`；负偏移对应 `146.309932474°`。有向交线实际构造的中心正方形逐边旋转 `±56.309932474°`，边长比为 `w/sin α=0.360555127546`，支持后者。`n=5` 的额外单片测试也按相同关系核对长度和旋转，避免把正方形的互余巧合当作通式。角度辅助函数并不参与 In[3018] 的 `RenderTile` 委托；模块把所得值明确标为 `geometricTwistAngle`，没有复制相互冲突的 In[3012] 表达式，也不推测原会话为何保存该源码。

两片各生成 16 点、24 边、9 面；其共享水平边反向重合，共边删除和共线整理后为 24 点、38 边、15 面。两中心环保留各自 `VVVV`；CP 无零长、重复或交叉边，局部 Kawasaki/Maekawa 检查通过。逐面 180° 反射 FF 保持每面所有顶点对距离，闭合误差约 `6.75×10⁻¹⁶`。[专项测试](../backend/test_tessellation_unit_regular_offset.py) 固定这些几何和来源参数，也核对角度公式冲突及无效输入。

独立 [层序脚本](../scripts/verify-unit-regular-offset-in3019.ts) 先将当前产品管线的 CP 与具名 Python 模块逐边、逐赋型、逐面和逐点对照，再执行 `prepareTessResult → tessFlatInput → computeFlatGeometry → recomputeFlatLayers`。保存例在当前引擎的静态层序约束下为 `solved`、恰 **1 个解**。这不证明连续无碰撞折叠路径、有厚度纸张的可制造性或原 Wolfram 图形的隐藏层序。具名 Python 模块仍返回 `adoptable=False`、`layerOrder=not_checked`，因为它本身没有执行或接入完整层序求解。

在 `workbench` 复现：运行 `.venv\Scripts\python.exe -m unittest discover -s backend -p test_tessellation_unit_regular_offset.py`，再运行 `node_modules\.bin\tsx.cmd scripts\verify-unit-regular-offset-in3019.ts`。
