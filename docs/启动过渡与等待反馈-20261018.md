# 启动过渡与等待反馈

本轮实现源码中的启动反馈，沿用折纸工坊现有图标、暖白与森绿配色。未生成新的桌面发行版，现有 v0.13.27 EXE 仍是此前冻结的发布文件。

## 启动顺序

| 阶段 | 显示与行为 |
|---|---|
| 便携版解压 | `portable.splashImage` 使用 `build/icons/startup.bmp`，在 NSIS 解压前显示中文品牌画面。由 `package:icon` 同步生成 560×360 的标准 24 位 BMP，使用已有图标，不增加第三方依赖 |
| Electron 接手 | 独立沙箱启动窗加载本地 HTML/CSS，显示现有折纸图标与轻量折线动画；仅加载少量本地资源，不等待工程库／计算服务完成 |
| 服务初始化 | 显示“正在启动本机服务”，以实际服务 ready 消息推进阶段 |
| 工作台载入 | 显示“正在打开工作台”，等待前端根组件实际提交及 Chromium 窗口可绘制；先显示主窗口，再销毁启动窗 |
| 等待较长 | Electron 启动阶段超过 8 秒后提示启动时间较长，可继续等待或退出重试。不显示虚构百分比，不添加最短停留时间 |
| 启动失败 | 错误页给出原因、打开日志文件夹和退出入口。服务启动有 20 秒超时，工作台准备有 30 秒超时。启动窗本身失效时不阻塞正常主窗加载；错误页也失效时使用原生错误框退出 |

NSIS 的静态画面会在启动 Electron 前销毁，Electron 加载窗随后接手；这是两段反馈，不宣称原生画面能够播放动画或与 Electron 完全无间隙。原生解压图没有取消交互，因此没有绘制伪关闭按钮。Electron 接手后的退出按钮走实际主进程取消和服务清理流程。

## 约束

| 项目 | 要求 |
|---|---|
| 真实状态 | 阶段对应真实初始化事件，主界面就绪就立即进入，不等待动画播完 |
| 动效 | 仅动画化图标中已有的折线；系统启用“减少动态效果”时显示静态图标，仍保留文字反馈 |
| 安全 | 启动窗独立临时 session，保持 sandbox、contextIsolation，关闭 Node 与外网；IPC 核对发起窗口、主 frame 和精确本地页面 URL |
| 失败与取消 | 迟到 ready 消息不得覆盖失败或重新打开已取消窗口；关闭启动窗不删除工程或恢复稿，退出后结束自己的服务和端口 |
| 启动画面本身失效 | preload 错误立即回退；本地加载最长 15 秒、页面显示后 3 秒内未收到首次成功渲染确认则回退。确认核对主 frame 和本地 URL；等待本机服务时不触发已经完成 UI 确认的检测。业务错误页尚未可操作时仍保留检测，必要时调用主进程原生错误提示并退出 |
| 体积 | 延续依赖去重、独立 sourcemap、完整离线引擎及源码／许可方案；新增 BMP 是启动器资源，不恢复重复 npm 运行依赖 |
| 验收 | 分别检查正常、慢启动、取消、失败及减少动态效果；未来实际打包时还须直接启动最终 Portable，确认解压前静态画面和 Electron 接力都出现 |

## 参考与边界

借鉴 Oriedita v1.1.3 “先显示品牌加载窗，再初始化，主界面就绪后销毁加载窗”的顺序。[官方主入口](https://github.com/oriedita/oriedita/blob/v1.1.3/oriedita/src/main/java/oriedita/editor/Oriedita.java)在初始化前调用 `LoadingDialogUtil.show()`，再调用 `hide()`、`afterStart()`；其[官方加载窗](https://github.com/oriedita/oriedita/blob/v1.1.3/oriedita-ui/src/main/java/oriedita/editor/swing/dialog/LoadingDialog.java)绘制应用图标，并非动画或真实进度条。

NSIS 时机依据当前锁定的 `node_modules/app-builder-lib/templates/nsis/portable.nsi`：`.onGUIInit` 显示 BMP，解压完成后销毁 `BgImage`，随后 `ExecWait` 启动应用。后续升级 builder 时须重新核对该顺序。完整发行要求见[打包与体积控制要求](打包与体积控制要求.md)。
