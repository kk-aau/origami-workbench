## 原式分支与局部正则性

取单位切线 `T=(-sin u,cos u)`、左法向 `L=(-cos u,-sin u)`，原左母线 `rL=L`，所以 In[3983] 的 `cotρL=(T·rL)/(L·rL)=0`。此圆弧速度和有向曲率均为 1。记 `t=tan(k u/2)`、`D=√(k²+t²)`；在 `k>0,u>0` 的保存例分支上，原式的 `expr1=tan(γ/2)cotρL−γ′/(ds κg)=−k`，`expr2=D`，`cρR=−k/D`，`sρR=t/D`。代回原版右母线的二维旋转，唯一得到

```text
rR(u) = −(k/D) T(u) − (t/D) L(u).
X_L(u,v) = f(u)+vL(u),   X_R(u,v) = f(u)+v rR(u).
```

这是由既有左侧母线、折角和原版符号分支确定的右侧方向，不是任意选取的旋转。若 `u=0`，`t=0` 且右母线与切线反向，右带的折痕处雅可比为零；因此范围从 0.001 开始，`k=0` 也被拒绝。

令 `δ=atan(t/k)`，对连续曲面直接微分，得到有向面积雅可比：

```text
J_L(u,v) = det(∂uX_L,∂vX_L) = 1−v,
δ′(u) = k²(1+t²)/(2(k²+t²)) > 0,
J_R(u,v) = det(∂uX_R,∂vX_R) = −t/D−v(1+δ′(u)) < 0  (u>0,v≥0).
```

因此左带必须在 `v=1` 圆心焦线前停止；右侧的焦线只在负向母线距离 `v=−(t/D)/(1+δ′)`，正向带没有局部焦线。两侧共享 `v=0` 的同一折痕。该判定仅证明所给开带的**局部浸入正则性**；未证明整个图像全局单射、无交、自碰撞或运动可达。没有成对三维初值，故不能按第一基本形式认证三维折面，也不生成面、边或可采用工程。

## 实现与验收

`backend/tessellation_curved_across_right_linear_angle.py` 提供连续二维 `frame`、`surface`、`signed_area_jacobian` 和只读采样。`src/app/curvedAcrossRightLinearAngle.ts` 以同一公式驱动“镶嵌设计 → 空间构造 → 线性折角跨右侧 · 二维”入口；`src/components/CurvedAcrossRightLinearAngleDialog.tsx` 显示左右直纹带、当前折角和来源／限制。修改非法参数时保留上一个有效图形，预览不写当前作品。

专项验证：Python 5 项、TypeScript 4 项通过，覆盖 In[3983] 的符号分支、保存例端点的**推导值**、独立有限差分核对有向雅可比、正负号与焦线前宽度、畸形和越界输入。真实 Chrome 浏览器验收见 `output/playwright/p45-linear-across-browser-report.json`：1000×720、390×720 两种视口，入口可打开并关闭，保存终点折角为 45.00°；斜率调到 0.8 时显示 72.00°、右边界随之变化；左宽输入 1 被拒绝且原图保留；重置恢复保存值。没有页面异常，桌面无溢出，窄屏控制区与图示不重叠，浏览器本地存储在预览前后相同。截图为 `output/playwright/p45-linear-across-1000x720.png` 和 `output/playwright/p45-linear-across-390x720.png`。

未实现：原版任意函数的符号 `FoldAcrossRight2D`、`NFoldAcrossRight2D` 的插值算法／误差界、同一线性折角输入的三维初值反求及二维／三维第一基本形式匹配、精确直折痕 CP/FOLD、全局纸面边界与无交运动。另一个独立的**常折角圆锥**成对子域见 `Origamica第45节跨已有曲折圆锥子域-20260924.md`，不能将其三维曲面移用到本例。
