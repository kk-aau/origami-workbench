## 前因后果及历史对比

旧实现先尝试完整页面，再逐步把可用步骤补进空格。完整页邻接搜索失败后，补排允许远距离父子；只要输出曲线不相交，就可把内侧节点的出口绕到页边。因此“占满九格”不代表存在可读的树形走线。05 的格距交换只能局部改善，不能建立“每条树边必连邻格”的不变量。

## 解决方法与边界

| 项目 | 实现 |
|---|---|
| 建树 | 使用现有 `branchForest` 的父子关系和待排拓扑顺序；过程图也作为独立节点处理 |
| 占格 | 从已满足父节点条件的候选中逐个放置；本页子节点只能占父节点上、下、左、右的空格；每格只占用一次 |
| 回溯 | 无法延伸时撤销当前格点，换空格或换另一条已就绪分支；相同占格状态去重 |
| 跨页 | 新入口从左侧开始；尚未结束的分支保留通往右侧的空通道，不允许出口穿过同排其他节点。跨页仍使用既有实际曲线碰撞与切线检查 |
| 排不满 | 保留搜索得到的最大合法部分页，未选节点留在待排队列；不能删除工程步骤。所有跨页边重新生成 |
| 自动预算 | 每页最多 24,000 次搜索访问，保留已找到的合法结果；属于自动预览布局预算，不涉及手动几何／纸层计算时限 |
| 适用范围 | 当前横向自动蛇形分支页；已手调曲线、固定节点、显式页步数、竖向入口继续走既有兼容逻辑。不宣称任意树都能最少页数或填满每页 |
| 未采用 | 源码中试验性的“大转向阈值”已完全撤回；`diagramPDFBranchCrossings.ts` 恢复原始哈希。没有改 PDF 样式、折叠数据或已交付 tauri.90 |

## 同日追加：跨页跳过一页，以及分支分层回溯

| 字段 | 追加记录（保留上面的首轮结果） |
|---|---|
| 触发 | 用户打开首轮修复后的软件，在第 9—10 页双页预览看到粉色 58A.B 标“续第 11 页”，下一步没有在第 10 页接续 |
| 已确认原因 | 首轮网格搜索只验证选中节点的邻接、出口和完整性，没有要求接入所有已开放分支；为填满第 10 页，它延长了紫色分支并把粉色入口留到第 11 页。119 节点完整、不相交、父子相邻不等于跨页连续 |
| 用户补充 | B 受阻先回到 B 自己最近仍可换方向的节点，试尽 B 后再回退 A 的上一可选节点；A 改向后重新尝试 B |
| 连续性修复 | `fitBranchPage` 从待排队列识别父节点已在前页的全部入口；合法页必须包含它们。搜索为这些入口预留空位和左侧格点，容量不足回溯前页，不能挤掉某一条分支 |
| 回溯顺序修复 | 就绪节点由树的深度优先顺序组织，让 B 的入口及后续转向保持在同一回溯栈；B 的方向用尽才退回 A。入口仅预留空间，不预先固定所有分支走向，以免 B 的入口早于 A 的路径进入栈而错退 A |
| 旧保护／规则变化 | 节点仍只能正交相邻、不重占格、不横跨两列。四分支超过三行入口时允许把前页分叉节点一起后移，因此更新旧测试中“父节点固定留前页、后页至少六格”的期望，改验父节点后移、分支完整、所有跨页相邻和至少五格；不是取消不相交或完整性断言 |
