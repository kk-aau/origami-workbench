- 新问题复制 [TEMPLATE.md](TEMPLATE.md)，编号为 `ISSUE-YYYYMMDD-NN`，日期按首次可确认的反馈日期；旧日期未知就使用建档日期并说明。文件名为 `<编号>-<简短主题>.md`。
- 收到反馈先写事实；分析后补原因及历史比较；修复后补方案、受保护行为、新旧回归结果；交付后独立更新包版本及验收状态。未知字段明确标为待确认。
- 每次复发追加一行“发生记录”，保留旧触发和结果。确认为新根因则新建问题，并在两份记录中互链。重复报告不作为新的已修复问题计数。
- 检索顺序：完整报错及关键短语 → 用户动作与状态变化 → 源码文件／函数 → 被改动的容差、过滤或缓存等保护 → 相关历史测试。分析完当前因果链后做一次比较，根因或方案变化时再做一次。
- 关联类型：同因／复发／修复引入的回归／上下游影响／共享机制但不同故障／仅现象相似／待确认／当前未发现关联。写证据及差异；不能仅凭同一个错误词或同一文件判定同因。
- 症状状态、修复状态、验证状态、交付状态分开写。没有旧案例、跳过检测、未做 UI 或实包验收，都保留为未决项，不能只写“已解决”。
- “对应文件”区分用户输入、最小夹具、诊断入口、实际改动源码、测试与证据。未确认改动的文件写“排查入口”，不冒称已修改。
- 私人工程原件不进入本目录；登记匿名案例标识及必要状态，原件定位、完整日志和敏感路径只留在本机隔离目录。可共享最小夹具去除无关内容。
