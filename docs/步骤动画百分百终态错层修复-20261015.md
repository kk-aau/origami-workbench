# 步骤动画 100% 终态错层修复

日期：2026-10-15

## 结论与证据

用户截图中的 CP3 → CP4 在 100% 时出现露出下层颜色的现象。本轮用独立工程复现了同类问题：只折上层纸角时，活动纸角的一部分在完全接触时被下面的纸张盖住。再构造四步工程，覆盖预折、中线折叠、上层纸角预折、上层纸角实折，以及主图翻面、旋转 37° 后的 CP 映射。

核心错误位于刚体变换的精确半转计算。它产生的虚假离面残差使渲染器拒绝本来正确的纸层关系，随后按深度绘制而出现错层。

| 检查环节 | 实际结果 |
| --- | --- |
| 100% 指令角度 | 正确到达原目标 ±180° |
| 终态材料关系 | 新纸角与下面两面的层序正确，未发现缺行或符号反转 |
| 刚体旋转 | `Math.sin(Math.PI)` 约为 `1.22e-16`，原本共面的纸角被制造出约 `3.10e-17` 的高度 |
| 共面判断 | 原算法只计入坐标存入 Float32 的舍入误差，没有将三角函数的非零残差当作数学上的零 |
| 渲染结果 | 重合纸面的可信层序被拒绝，部分三角片抢占了应由纸角覆盖的位置 |

在固定的 1000 × 600 独立探针中，纸角应显示 5,119 个红色像素，修复前仅显示 2,576 个，缺失 2,543 个。修复后恢复 5,119 个，与正确外层完整纸面的对照一致。正式回归使用单独绘制的实际最外完整纸面作为参考，检查纸角内部全部采样点，不借助增加间距或切割纸面确定颜色。

## 实现

修改 `src/engine/simStepRigid.ts` 的 `around()`：

- 旋转角度以原指令的度数传入；只有 `degrees / 180` 是精确整数时，使用数学上的 `sin = 0`、`cos = ±1`。
- 接近 180° 的中间姿态继续使用真实三角函数，不吸附到终态，也不降低折叠进度。
- 保留原刚体连接、固定点、边长、闭环与折角验证。

本次没有改宽渲染容差，也没有改变材料顶点、原始三角网格、纸层关系或折叠目标。起态与终态继续使用完整 100%，纸层间距继续关闭。

| 同一纸面采用不同三角化或绘制顺序 | 原网格、另一合法三角化、反向绘制均显示同一外层纸面 |
| 从背面看、自由旋转视角 | 正面、背面及带滚转的斜视角检查通过 |
| 世界坐标旋转、平移、连续多个半转 | 正式用例覆盖连续五次半转、近零旋转、`1e-12` 和 1000 坐标平移；独立单面参考一致 |

| 中途被其他纸面挡住的动作 | 继续经过原连续路径碰撞检查、分段规划或拒绝不合法路径；本修复不改变规划约束 |

## 边界

本次确认并修复的是步骤动画精确平折时的数值错误。未提供可信层序的普通三维模拟、透明显示、退化纸片，以及大型模型超出层序分析预算或解析接触无法证明的情况，不应通过强行改变绘制顺序来伪造正确结果。大型模型预算耗尽时，当前时间线可能仅保留已确认关系；它是另一项边界，本轮小模型的复现没有触发该限制。
