# Origamica 第 36 节：单位圆内接多边形居中扭转两种具名拼块

只读笔记本 `tmp/Origamica-15.0-reference.nb` 中，`UnitCyclicPolygonCenteredTwistTile` 和 `UnitCyclicPolygonCenteredTwistAltTile` 是稳定的具名入口。原版保存的居中扭转绘图输入只有 **四边形子域**：两个保存双块可得到相邻面闭合的逐面等距 2D 平折几何，并已通过[受限凹面层序生产入口](受限凹面层序生产接入-20260924.md)，各为 **`solved`、精确 1 解**。2026-09-27 又以原版母六边形 Out[359] 作解析锚点，增加 In[3041] 通用包装公式的受限单六边形本地组合；还以 In[357]/[373]/[378]/[3041] 通式增加无专属保存图或数值 Out 的不规则八边形单片。六边形和八边形扭转均为本地公式推演，层序结论不代表 Mathematica 数值 CP/FF Out 逐点等价或连续折叠路径证明。

| 具名入口 | 原版定义与参数 | 保存输入 |

| `UnitCyclicPolygonCenteredTwistTile` | In[3041]，约 226777–226796 行：`UnitCyclicPolygonVertices[angles,side,is]` → `PolygonCenteredTwistTile[verts,w,τ,types]`。 | In[3042]，约 226803–226882 行：`τ=80°`。 |

两例共享 `angles={75°,85°,95°,105°}`、`side=1.2`、`is=2`、`w=.1`；第一块中心四边全 `M`，第二块全 `V`。`JoinTiling` 中第二块给 `{1,2,2}`，即双方第 2 边反向接合。保存单元调用 `EmbedTiling` 画 Tiling、CreasePattern、FoldedForm2D；这些单元没有可机比的数值 CP/FF **Out**。笔记本绘图不能充当整片层序或连续无碰撞折叠的证书。

## 四边形输入语义及实现范围

原版 `ConcyclicCenterAngles` In[357] 和 `UnitCyclicPolygonConcyclicInfo` In[373] 对偶数边数 **忽略输入最后两角**，通过内角和及交错和补足；后者用指定边长求交错中心角参数，`UnitCyclicPolygonVertices` In[378] 取其顶点。因此保存的 `{75,85,95,105}` 实际约束是 `{75,85,105,95}`，第 3、4 个原输入仍被保留为来源数据。该凸四边形由第一边 `(0,0)→(1,0)`、前两内角及第 2 边长 1.2 唯一确定：顶点约为 `(0,0),(1,0),(.8954131087,1.1954336377),(.3462610835,1.2922639563)`；外接圆心约 `(.5,.5585475708)`，半径 `.7496501776`。四顶点到圆心的距离在测试中一致。

`backend/tessellation_unit_cyclic_centered.py` 独立提供两个具名参数入口：将四边形语义转为凸的单位四边形顶点，然后用现有 `polygon_pleat_tile` 建立 `offset=0` 的 CP；Alt 用原公式换算褶角。返回原四角、实际四角、指定边及序号、外接圆、具名类型、M/V、褶宽、输入角及中心顶点；Alt 另保留原扭角。双块辅助构造通过第 2 边中点的 180° 刚体旋转接合，逐块保留 `sourceIndex` 和原始参数。本模块只覆盖 `n=4`，不推断一般圆内接单位多边形或额外 Brocard 约束；参数须为严格凸四边形、`is∈{2,3,4}`、`side∈[.05,5]`、`w∈[.05,.8]`、四项 M/V，角度限 `[1°,90°)`。底层还会拒绝退化及不满足局部条件的组合，这些数值范围不是全域可折保证。

保存双块在本项目中各为 **26 顶点、40 边、15 面**。CP 几何与局部 Kawasaki／Maekawa 条件均通过；以同一 CP 逐面刚体反射得到的 2D FF 闭合误差，普通型约 `6.44×10^-10`、Alt 约 `9.88×10^-10`，每个面的任意顶点对距离保持。上述计数与 FF 坐标是本项目的计算结果，原版没有对应数值 Out 可逐项比对。`scripts/verify-unit-cyclic-centered-in3042-3045.ts` 先把通用请求与具名模块的边索引、M/V 赋型、面索引逐项精确比较，顶点容许 `10^-8` 的浮点序列化差；两例 CP 身份均通过，再对同一 CP 执行 `computeFlatGeometry → recomputeFlatLayers`。

两例 `computeFlatGeometry` 均为 `ready`。**面 6 和面 8** 是凹五边形：普通型面索引分别为 `[14,17,12,10,6]`、`[13,15,19,11,8]`；Alt 为 `[15,17,12,11,6]`、`[13,14,19,10,8]`。这些面在 CP 和反射后的 FF 中均有正负混合的非零连续转角，非相邻边没有交叉。初次审计曾因凸面门禁返回 `unsupported`；后续 `src/core/concaveLayers.ts` 在三角片上生成覆盖约束，搜索前统一绑定每个原面对的层变量，核验面积、绕向、原边与邻接，内部片段不会自由排序。生产 `recomputeFlatLayers` 现在各得精确 1 解，原面正背局部区域分别 361、365 个全部有序；没有强造全局绘制顺序。具名 Python 模块不运行层序，仍标记 `layerOrder=not_checked`、`adoptable=False`，工作区需经过当前输入的独立 Worker 结果。

## 2026-09-27 母六边形 Out[359] 锚定的居中单补片

全笔记本 `UnitCyclicPolygonCenteredTwistTile`、`UnitCyclicPolygonCenteredTwistAltTile` 的保存绘图输入仍只有 In[3042]、In[3045] 两个四边形例，均无可机比数值 CP/FF `Out`。原版 In[357]/Out[359] 则保存了六边形母多边形的**零交错**圆心弧角：输入内角 `{128°,119°,118°,115°,0,0}`，末两项按原版规则被忽略并重算为 `114°、126°`；输出为 `{58°,64°,60°,70°,62°,46°}`。这份 Out 只锚定母多边形的弧角，未给六边形扭转 CP。

在 In[373] 默认的首边单位长、`side=1,is=2` 下，偶数边形的弧角写为 `gᵢ=bᵢ+(−1)ⁱζ`。第 1、2 边等长且各弧角限制在 `1°–179°`，故 `58°+ζ=64°−ζ`，唯一得 `ζ=3°`；实际弧角为 `{61°,61°,63°,67°,65°,43°}`。圆心是 `(1/2,cot(61°/2)/2)`，半径为 `1/[2sin(61°/2)]`。依弧角累加的六顶点约为 `(0,0),(1,0),(1.484809620246,0.874619707139),(0.924116803996,1.738010930346),(−0.152778288867,1.586663195108),(−0.444578582469,0.569034636484)`；源码与独立 Python 母多边形实现逐点误差小于 `10⁻¹¹`，共圆与严格凸也已复核。

`src/app/unitCyclicSource.ts` 在保留旧四边形公式及工程字段的同时，增加受限的六边形单补片：前四角可编辑、末两项保持原版忽略用的 `0` 占位，第 2 边定长，中心弧角必须在 `1°–179°`，多边形须严格凸、共圆且有限；`w∈[.05,.8]`、`τ∈[1°,90°)`、六条中心边 M/V 可编辑。此入口只使用 In[3041] 的 `UnitCyclicPolygonVertices → PolygonCenteredTwistTile` 委托语义，单块 `w=.1、τ=80°、MMMMVV` 是**本地组合推演**，不称 In[3042] 或 In[3045] 的原版保存结果。初步通用生成得到 CP 24 点／36 边／13 面，几何和局部条件通过；十五种四山二谷赋型扫描都在当前零厚度模型得到精确 1 解，但每次采用仍以当前工作区异步层序检查为准。

来源 `unitCyclic` 在工程读回时重新计算顶点、面及逐边 M/V／褶宽／褶角，不接受把六边形冒作 Alt、双块或更广的偶数边族，也拒绝更改占位角、定长边号、顶点、扭转配方后冒用旧来源。编辑网格 JSON 不变时保留来源，改动几何后清除来源。`tests/app/unitCyclicSource.test.ts` 覆盖 Out[359] 六弧角、默认边约束后的六顶点、来源严格回读、防伪和旧 n=4 预设兼容。

`backend/tessellation_unit_cyclic_centered_hexagon.py` 是独立具名 Python 校验，不宣称 Wolfram 六边形扭转数值 Out。`scripts/verify-unit-cyclic-hexagon-centered-out359.ts` 将工作区通用 CP 与该具名构造逐边、逐面、逐来源及 M/V／折角核对：同为 24 点／36 边／13 面，母多边形最大坐标差 `4.58×10⁻¹⁶`，完整 CP 最大坐标差 `8.07×10⁻¹⁰`。通用 CP 的逐面等距平折几何为 `ready`，原面受限层序为 `solved`、精确 1 解，正背各 309 个局部区域有序。它们只证明本项目这份零厚度重建，不证明原版六边形扭转 CP 的数值身份或连续折叠路径。`scripts/experiments/p03CyclicHexProbe.ts` 的 15 种四山二谷扫描仅是此母六边形和同一 `w/τ` 下的局部经验，不扩大具名预设承诺。

## 2026-09-27 八边形有界公式推演

全笔记本没有 `UnitCyclicPolygonVertices` 或 `UnitCyclicPolygonCenteredTwistTile` 的 **n=8 专属保存输入、绘图、顶点数值 Out 或 CP Out**。正多边形母图 In[434] 也是通用定义，显式示例止于 n=4/5/6。因此此工作区八边形入口只组合原版 In[357] 偶数角补全、In[373] 第 `is` 边定长选定交错自由度、In[378] 母顶点和 In[3041] 居中拼块委托语义，绝不标为原版八边形保存例。

本地具名预设取非正八边形输入角 `{140°,135°,135°,135°,130°,135°,0,0}`、`side=1,is=2`，后两项是原版忽略占位；重算有效角为 `{140°,135°,135°,135°,130°,135°,135°,135°}`。`ConcyclicCenterAngles` 的零交错特解是 `{40°,50°,40°,50°,50°,40°,50°,40°}`，第 2 边与首边同为 1 唯一选出 `ζ=5°`，实际中心弧角是 `{45°,45°,45°,45°,55°,35°,55°,35°}`。外接圆心为 `(1/2,cot(22.5°)/2)`；八顶点由 In[373]/[378] 的累加弧角公式确定，前后端母顶点最大差 `4.97×10⁻¹⁶`。若六个可编辑角或定边长使补角越出 `1°–179°`、内圆心分支不闭合、几何不严格凸／共圆或坐标越界，来源直接拒绝；本工作区只开放 `is=2`、单补片、居中褶角，未泛化 Alt 或双块。

局部组合取 `w=.1、τ=80°、MMMMMMVV`。`backend/tessellation_unit_cyclic_centered_octagon.py` 与工作区通用生成均得 **32 点／48 边／17 面**；`scripts/verify-unit-cyclic-octagon-centered-formula.ts` 逐项核对边、M/V、折角、面和逐面来源，完整 CP 最大坐标差 `4.00×10⁻¹⁰`。逐面等距 2D 平折几何 `ready`，工作区原面受限层序 `solved`、精确 1 解，正背各 748 个局部区域全部有序。具名 Python 模块自身不跑层序，仍声明 `layerOrder=not_checked`、`adoptable=False`；实际采用必须通过当前输入的工作区异步层序。上述均只证明本项目零厚度公式重建，不证明原版 n=8 数值 Out 身份或连续折叠路径。

`unitCyclic` 来源 JSON 对八边形要求六个有限输入角、两个严格为 0 的占位角、第 2 边、八条中心 M/V、单片及精确扭转参数；读回重新计算顶点和 CP 请求并拒绝伪造来源。编辑网格 JSON 不变时保留来源，改顶点或扭转参数后清除来源；旧 n=4 双块／Alt 与 n=6 单块工程继续按各自规则严格回读。工作区同一“圆内接”入口提供八边形选项，显示“公式推演”和无保存 Out 限制，六角输入分两行、八条 M/V 分两行。
