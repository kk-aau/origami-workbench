# 折痕文档与折序绘图删除

2026-10-18，源码更新。当前发行版 EXE 未重新打包。

## 操作入口

在“折痕文档”或“折序文档”中，每张文件卡片底部均有“删除”。确认框显示文件名称及不可撤销说明，默认聚焦“取消”；确认后等待删除完成，期间禁止重复提交或取消正在进行的操作。删除失败会保留确认框并显示原因。

| 情况 | 结果 |
|---|---|
| 删除当前文件 | 关闭对应编辑内容、撤销历史及相关任务，返回文档库 |
| 删除其他文件 | 当前正在编辑的内容保留 |
| 取消确认 | 文件、草稿与编辑状态均保留 |
| 删除请求提交前失败 | 保留原内容，允许重试 |
| 删除已提交，但残留副本清理失败 | 显示警告，文档仍保持已删除，不误报为整体失败 |

此操作删除本机文档库中的对应文档，不影响用户另行导出的文件或外部备份。删除后无法通过编辑器的“撤销”恢复。

## 数据处理

| 文档库 | 清理及保护 |
|---|---|
| 折痕文档 | 清理当前保存目录下该 ID 的手动保存、独立草稿及各自备份；仅清理明确匹配该 ID 的磁盘和浏览器恢复稿；保留其他文档及无法识别归属的损坏恢复稿 |
| 折序绘图 | 先提交移除目标的文档索引，再清理该文档的保存、草稿及旧修订；仅清理内容匹配的旧版全局草稿，并保留删除标记防止后续迁移复活 |
| 最近打开与分类 | 清理目标 ID 的记录，保留文件夹和其他文档的记录 |
| 自动保存 | 删除开始时暂停新写入，等待已有写入结束；删除当前文档后取消草稿计时器和迟到任务，解除原 ID 引用 |
| 未处理的恢复提示 | 删除提示对应文档后，继续展示另一份仍保留的恢复副本；用户已主动处理或关闭的提示不会重新弹出 |

两类文档使用独立存储；即使 ID 相同，删除其中一类也不影响另一类。

折痕删除接口 `DELETE /api/projects/{uuid}` 沿用本机会话、来源、Host 和 UUID 校验，与工程保存、目录迁移共用写入队列。先将目标文件移至同目录临时位置，全部移动成功后才清理；移动失败时尝试回滚。拒绝目录或符号链接，不执行递归删除。提交后临时副本清理失败只报告警告，避免编辑器因误以为删除失败而重新保存原 ID。
