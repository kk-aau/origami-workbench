# DXF 刻字软件兼容修复与验证

针对用户实际反馈“普通 DXF 能导入，优化加工 DXF 不能导入”，本次对比实际成功／失败样本并修复加工导出。保留原 CP、普通导出及已有工作；没有覆盖桌面原文件，没有操作机器或发布。项目没有 Git 元数据，本次修改前的相关文件 SHA256 记录在 `output/audits/cp-dxf-compat-baseline-1003.json`。再次核对首轮 1,499 文件基线，只有已授权的原 `src/App.tsx` 入口接线改变，结果存于 `output/audits/cp-dxf-compat-preserved-existing-1003.json`；桌面三个原始 DXF 的 SHA256 与审计开始时一致。

## 问题证据

| 用户实际样本 | 版本／实体 | 独立 CAD 审计 |
|---|---|---|
| `环状镶嵌.dxf`，用户确认可导入 | AC1009 / R12，660 个 LINE | ezdxf 1.4.4：0 错误、0 修正 |
| `旋转对称壶体.dxf`，用户确认可导入 | AC1009 / R12，792 个 LINE | 0 错误、0 修正 |
| `Flasher 旋转折叠.加工优化.dxf`，用户确认不可导入 | AC1009 / R12，25 个旧式 POLYLINE，456 边，私有扩展数据 | 0 错误、0 修正；能被通用 CAD 解析不代表刻字软件支持 |

旧加工输出在 R12 头中加入 `$INSUNITS`，该变量在 R2000 / AC1015 才支持，存在版本一致性问题。实体种类、APPID / XDATA 及私有头注释也与成功样本不同。已消除这些兼容风险；尚未获得目标软件名称／版本或真实导入结果，不能把拒绝原因归结为单一字段。

## 实现与使用

| 「优化加工导出」中的格式 | 实际写出 | 连续路径与单位 |
|---|---|---|
| SVG · 连续路径 / mm | 保留原连续 M/L 输出 | 原毫米坐标和 viewBox，连续路径 |
| DXF R2000 · 标准连续多段线 | 附件原完整 AC1015 模板，标准 LWPOLYLINE；规范句柄、所属模型空间、子类与表结构 | 保留连续路径，声明毫米；软件必须支持该版本和实体 |
| DXF R12 · 普通 LINE 兼容版 | 复用现有普通 `exportDXF` 的空文件结构，填入优化后的 LINE 顺序 | 实际每边一个独立实体，无法编码连续落笔；按一单位等于一毫米导入 |

两种 DXF 均只应用既有一次 `(x, -y)` 转换。不同加工组保留独立标准图层；完整加工设置和每条来源映射保留在独立 JSON 核验报告，不写私有 DXF 来源扩展。重复提示、明确允许同设置合并、加工次数、无跨空白落笔、取消后台任务继续生效。

界面会按当前实际输出格式展示预览与指标：R12 版按 LINE 实体数量显示独立线段及起点，不声称拥有连续版的路径数优势。它保留边顺序和几何空走统计，但软件可能逐边抬笔、重排路径；该统计不代表真实机械动作或时间。改变设置仍使三个格式的旧导出全部失效。
