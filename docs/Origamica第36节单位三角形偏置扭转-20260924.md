# Origamica 第 36 节：单位三角形偏置扭转具名拼块（2026-09-24）

原笔记本 `tmp/Origamica-15.0-reference.nb` 中，`UnitTriangleVertices`（20335–20373 行，In[366]）以 `(0,0)→(1,0)` 为单位底边，第三顶点为 `sin B/sin C·(cos A,sin A)`，其中 `C=180°−A−B`。`UnitTriangleOffsetTwistTile` 的具名参数是 `{angles,w,d,types}`（226347–226426 行）；`RenderTile`（226481–226501 行，In[3038]）把它原样交给 `PolygonOffsetTwistTile[UnitTriangleVertices[angles],w,d,types]`。通用偏置拼块在 215825–215842 行（In[2919]）固定褶角 `π/2`，且仅当 `d>0` 时取逆时针方向。因此 `d` 是沿边中点的**有符号偏移**，尽管具名拼块说明文字 226382–226390 行误称它为“pleat angle”。

保存的 In[3039]（226508–226574 行）令 `angles={50°,60°,70°}`、`w=.1`、`d=.05`、`types={M,M,M}`，再把相同参数但 `d=-.05` 的第二片通过 `JoinTiling` 的 `{1,2,2}` 接在双方第 2 边。Python [具名模块](../backend/tessellation_unit_triangle_offset.py) 从这些源参数建立两片，按第二边中点半周旋转取得第二个源三角形，再用通用有向交线构造器做逐片 CP、拼合共边。这个受限 API 额外要求第三角与 `180°−A−B` 一致、三个角均至少 `1°`、褶宽落在通用构造器 `0.05≤w≤0.8` 的范围，且偏移不越过边界；这是本项目为可验证输入设置的限制，不是原 Wolfram 函数的报错语义。

相邻 `UnitTriangleOffsetTwistAngle` 的**源码输入** In[3030]（225983–226011 行）印出 `ArcTan[w/(2d),F]`，其中 `F=sin A sin B sin C/(1+cos A cos B cos C)`。对其 In[3031] 的 `.09,.06`，这个双参数顺序给 `36.829059608°`；但笔记本的**保存输出** Out[3031]（226030–226048 行）为 `22.843204806313516°`。反函数 In[3032]（226071–226099 行）明确给 `d=w F cot(α)/2`，保存 Out[3033]（226114–226134 行）又以 `α=22.8432°` 得 `d=.060000014068401`。因此具名模块使用该反函数的正确分支 `α=atan2(w F,2d)`，而没有复制 In[3030] 的冲突顺序。其 `α` 和 In[3034]/In[3035]（226195–226258 行）的 `w csc α`、`90°−α` 关系，也由构造所得中心三角形的逐边长度比和旋转角独立数值验证。这里仅确认保存参数的几何自洽，不断言当时 Mathematica 会话为何留下不同的输入与输出。

对保存例，单位顶点第三点为 `(0.592396265452,0.705990377592)`；正负偏移的中心扭角分别为 `29.321405663°` 与 `150.678594337°`，两个中心三角形的边长均为对应外边的 `0.204203228569` 倍。单片各得 12 点、18 边、7 面；第 2 边的两端严格反向重合，合并后 CP 为 18 点、28 边、11 面，中心边仍各为 `MMM`。本项目的 CP 无零长、重复或相交边，局部 Kawasaki/Maekawa 条件通过。逐面 180° 反射的 FF 保持每面所有顶点对距离，闭合误差约 `4.63×10⁻¹⁰`。这些数值是**本项目构造结果**；原笔记本在此只保存 Tiling/CreasePattern/FoldedForm2D 图形调用，没有可直接逐点对照的 Wolfram 坐标表，故不声称图元逐点等价。

独立 [层序脚本](../scripts/verify-unit-triangle-offset-in3039.ts) 从现有后端生成同组参数的 CP，先将边、赋型、面及逐点坐标与具名 Python 模块的 CP 对照，再经 `prepareTessResult → tessFlatInput → computeFlatGeometry → recomputeFlatLayers` 得到 `solved`、恰 **1 个**符合当前引擎约束的整片层序解。它是静态层序检查，不证明连续无碰撞折叠路径、有厚度纸张可制造性或原 Wolfram 图形的完整层序。具名模块仍返回 `adoptable=False`、`layerOrder=not_checked`，避免把独立 CP/FF 例误作已接入产品的可采用拼块。

复现：在 `workbench` 运行 `.venv\Scripts\python.exe -m unittest discover -s backend -p test_tessellation_unit_triangle_offset.py`，再运行 `node_modules\.bin\tsx.cmd scripts\verify-unit-triangle-offset-in3039.ts`。[专项测试](../backend/test_tessellation_unit_triangle_offset.py) 固定了 In[3030]/Out[3031] 的数值冲突、正负偏移的边上宽度端点及垂直褶线、中心 `M/V`、扭角/缩放/旋转、共享第 2 边和 FF 逐面等距。
