# 大工程速度优先计算

用户要求优先缩短完整计算耗时，允许以更多内存换取速度，并评估多核 CPU 与 GPU。完整区域、层序、接触约束及可见边界校验保持不变；不以硬件占用率代替性能结果，不跳过真实微小区域或提前发布部分结果。

## CPU 关系查询缓存

区域认证原先需要跨纸面行查询单向位关系。现在为适合的规模建立双向二位关系行：0 表示未定义，1／2 表示明确相对层序；增删纸面时从同一行查询两种方向。更大的稀疏索引仍使用原分页实现，不截断纸面数或伪造缺失关系。

对同一份已保存龙神精确拓扑、3,662,368 条已解关系交错进行八次认证测量：

| 指标 | 结果 |
| --- | --- |
| 完整区域数 | 1,828,791 |
| 认证中位耗时 | 10.284 秒 → 7.158 秒，减少 30.39% |
| 额外关系缓存 | 约 45.28 MiB |
| 完整证书 | 21,945,492 字节，八次与原证书逐字节 SHA 一致 |
| 固定扰动候选 | 547 个循环反例及其顺序一致，不生成成功证书 |
| 回归 | 19 项相关测试通过，包含六面以内 33,868 种有向完全图穷举、位边界和稀疏回退 |

上述只测量区域认证热点，不是导入、拓扑构建、候选求解和显示全部流程的耗时，不能宣传为整个龙神任务提速 30.39%。数据和脚本位于本机 `output/flat-unlimited-validation/region-tournament-speed-20261027.json` 所引用的证据目录。

这份缓存几何与此前实际浏览器重新计算的浮点几何属于不同测试输入；区域数量和证书不能混用。完整生产流程的结果应单独记录，参见[精确平折与显示验证](大工程精确平折与显示验证-20261027.md)。

## 多核完整区域认证

大工程把原有增删纸面遍历划分为经过校验的区域批次，使用共享内存传递双向关系行、遍历事件和完整证书。支持跨源隔离与 SharedArrayBuffer 的运行环境，按有效硬件并行数、可用分块和协议上限选择检查线程；本机实测使用 20 个线程，20 不是其他电脑的使用门槛。小工程、稀疏关系矩阵或不具备并行条件时，使用兼容的完整 CPU 路径。

主界面线程管理检查线程。检查线程异常、协议错误或数据不完整会唤醒求解线程、弃用故障共享数据并重新完整检查；取消操作立即终止求解及全部检查线程。成功证书必须覆盖全部真实区域，复制到独立数组后才能向后续显示传递。没有新增时限、面数或搜索节点截断。

候选 7 的首次多核实测在本机 Core Ultra 7 265K（20 核／20 线程）、约 48 GB 内存上，使用同一份缓存几何和精确拓扑完成全部候选求解：

| 指标 | 原路径 | 多核路径 |
| --- | ---: | ---: |
| 完整区域数 | 1,828,791 | 1,828,791 |
| 关系数 | 3,662,368 | 3,662,368 |
| 候选迭代数 | 79 | 73 |
| 完整求解耗时 | 1,005.51 秒 | 312.27 秒 |
| 最终证书 | 21,945,492 字节 | 逐字节一致 |

该口径缩短约 68.9%，包含遍历准备、20 个线程启动、全部候选和每轮完整关系校验，**不包含原始 CP 的导入、几何与拓扑构建，也不是整条应用流程耗时**。分块可能改变真实反例的发现顺序及迭代次数；最终完整证书仍必须通过所有区域校验。本机证据为 `.runtime/qa-complete-flat/dragon/complete-candidate-parallel-v1/summary.json`。

共享遍历事件约 87.55 MB，关系矩阵约 95.04 MB，最终证书约 21.95 MB，此外还有原始几何、约束与线程状态。以上为分别计量的主要缓冲区，不是整个应用峰值内存。

## GPU 实测及采用范围

本机 RTX 5070 Ti 的真实 WebView2 WebGPU 已验证可用。实验使用真实龙神区域，以整数运算计算覆盖顺序；16k 与 64k 区域批次的顶面、底面、深度和状态与 CPU 证书一致，缺失关系、非法关系及三环均正确拒绝。

64k 区域实验执行约 24.18 亿次有向关系校验，GPU 时间戳约 46.53 毫秒；分批调度的实际计算墙钟约 191.5–199 毫秒，上传约 62.6 毫秒，回读约 3.5–3.9 毫秒。这是批次实验，未运行整个龙神 GPU 认证；不能把按批次深度分布推算的约 1.30 秒当成全量实测。多核 CPU 完整区域认证的独立热点实测约 0.61–0.67 秒，因此当前 GPU 实验不足以支持替换生产认证路径。

本版采用有实际收益的 CPU 多核与共享缓存，继续保留原有 CP 绘制和三维模拟的 GPU 路径。GPU 区域认证仍是实验，不宣称生产求解使用 GPU。实际应用的冷启动完整流程及隔离兼容性另行验收；最终记录以同版本发行证据为准。

## 应用计时的环境边界

此前 834.311 秒完整 Worker 基线使用 Headless Edge 156；本版原生窗口使用系统 WebView2 155。新旧准备后的 CP 和重新生成的几何已经逐字节核对一致，但宿主及运行时版本不同，不能据此把时间差归因于纯算法优化，也不能称为严格同环境提速。新版原生完整流程时间独立记录；同环境、同输入的比例结论采用上面的 Node 缓存拓扑对照。

候选 7 以全新原生宿主、独立配置目录和正式导入／求解／检查 Worker 资源，从原始龙神 ORI 重新完成计算，不复用几何、拓扑或证书，也不设置额外浏览器堆参数。该轮正式计时期间没有并发构建、压缩或其他测试宿主启动：

| 阶段或结果 | 实测 |
| --- | --- |
| 原始 ORI 导入 | 0.565 秒，35,679 条线段 |
| 准备后的 CP → 完整双面结果与缓存核验 | 255.638 秒 |
| 原始 ORI → 完整双面，排除额外 SHA 计时 | 256.202 秒，约 4 分 16 秒 |
| 重新生成几何 | 19,491 面，与此前实际浏览器几何逐字节一致 |
| 正、反面区域 | 各 1,827,830 个全部验证，未确认项为空 |
| 完成后线程 | 导入、求解及 20 个检查线程全部释放 |
| 计算中途停止 | 在第一代检查尚未完成时触发，约 68.2 毫秒返回，未发布纸面结果 |

这是原生宿主内正式 Worker 计算管线的独立验收，不包含四工作区主界面的最终绘制时间；完整界面与最终 EXE 另行验收。计时证据位于本机 `output/playwright/complete-flat-webview2-cold-20261027/complete-report.json`；停止证据位于 `output/playwright/complete-flat-webview2-20261027/cancel-report.json`。首轮约 224 秒的结果只作为功能证据，因为初段曾有另一个空白测试宿主启动，不作为正式冷计时。

## 不同电脑的适配

候选 8 去除本机 20 核上限。有效核心数经过整数与范围检查后，按可用任务分块及协议上限分配线程；单核、缺失、非有限或无效核心数使用兼容串行路径。层序认证不依赖 WebGPU、独立显卡或指定显卡型号。

双向缓存与共享遍历仍是可选加速资源。大块缓存分配失败时，按具体分配位置识别资源错误，切换完整分页存储或串行认证；已失败的大缓存不重复分配。缺失关系、非法输入、覆盖集合错误及遍历自身错误继续报错，不得伪装为资源不足而绕过验证。浏览器粗略的 `deviceMemory` 不作为真实内存门槛。

不同电脑可以采用不同的加速路径，但认证规则相同；任何路径都必须完成全部真实区域。前述候选 7 的既有性能数据保留其原始口径，候选 8 的硬件能力模拟、原生实测和最终包验收另行记录。

候选 8 的 18 种原生 Worker 能力／资源模拟已通过，两代共 36 份证书逐字节相同，90 组负例保持拒绝；属于单机能力模拟，非多台实体电脑测试。在同一台 20 核机器的全新原生宿主中，原始 ORI 导入耗时 0.450 秒，准备后的 CP 到完整双面与缓存核验耗时 231.255 秒，原始文件到结果合计 231.706 秒（排除额外证据哈希），约 3 分 52 秒。两面各 1,827,830 个区域完整认证，自动使用 20 个检查线程，全部线程和测试宿主正常退出。没有复用几何／拓扑／证书或设置额外堆参数，计时期间没有其他构建、压缩或测试宿主启动。

候选 8 证据位于 `output/tauri-release-0.13.38-tauri.8/hardware/summary.json` 与 `output/playwright/complete-flat-webview2-tauri8-20261027/complete-report.json`。不同冷轮耗时存在波动，不把相对候选 7 的时间差宣传为这次兼容修复的额外提速。该流程仍不含主界面最终绘制；最终双 EXE 操作验收另行完成。
