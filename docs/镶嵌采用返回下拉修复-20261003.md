# 采用展开图副本后空间构造菜单失效

针对 Windows 免安装版：采用展开图副本进入折痕编辑后返回镶嵌，空间构造类型菜单不能直接展开，切换构造大类才能恢复。

普通 Chrome 的七种采用返回流程可操作；桌面存在 Chromium JavaScript 确认弹窗之后的窗口／渲染区焦点问题。此前仅在网页里替换 `window.confirm` 的回归，不能覆盖桌面原生弹窗。Electron 官方已有同类报告：[Windows 确认框失焦](https://github.com/electron/electron/issues/31917)，[主进程原生弹窗与 Chromium 确认框的差异](https://github.com/electron/electron/issues/51760)。本次用真实 Windows 弹窗验证新的主进程处理路径，不将旧自动化的弹窗应答视为已经关闭原生弹窗的证据。

| 修改 | 行为 |
| --- | --- |
| 工程替换及模型清空确认 | 桌面调用主进程 `showMessageBoxSync`，网页继续 `window.confirm` |
| 原生弹窗 | 绑定当前主窗口，默认取消，关框也取消；确认内容及两阶段确认次序保留 |
| 返回主画面 | 只在弹窗实际返回后恢复可见、非最小化窗口及渲染区焦点；不强制启用仍在模态状态的窗口 |
| IPC | 只接受同源主窗口主帧、有效短文本；仅在结果确定后回复一次，异常不批准替换 |
| 构造参数 | 采用与返回保留当前空间类型；无需切换构造方式恢复控件 |

## 验证

`npm run test:unit`：1969 项通过。`npm run test:desktop`：7 项通过，含打包依赖与确认 IPC 的安全、取消、异常、失焦恢复以及同步回复次数。`npm run build`：TypeScript 与 Vite 构建通过；保留已有体积警告。

`node scripts/verify-tess-return-electron.cjs`：12 项源码桌面回归通过。七种空间构造逐项确认实际进入折痕编辑、返回原类型、窗口启用及焦点、鼠标打开原生下拉菜单、键盘选择改变类型。另测取消不会进入折痕编辑。

最后两项使用真正 Windows TaskDialog，在测试进程内定位“确认操作”弹窗的取消／继续按钮，向该按钮发送事件并等待模态循环退出，再验证窗口及渲染区焦点与下拉展开。没有替换 `window.confirm`，没有用一个已失效的弹窗应答伪造关闭。自动化助手仅作用于当前隔离测试 PID 及指定弹窗标题。前七种的弹窗答案在主进程原生 API 上模拟，真实弹窗接受／取消另验。

打包后的验证另记在 `release/验收-v0.13.3-20261003.json`：源码运行通过不等于免安装 EXE 验证通过。没有修改镶嵌数学引擎、CP 加工几何或 DXF 格式；本轮不重复宣称刻字软件导入或机器试压已经验证。

实际免安装 EXE 的相同 12 项专项检查及既有 137 项桌面检查通过。免安装启动器不转发 Playwright 所需的调试输出；使用 `node scripts/verify-tess-return-electron.cjs release/Zhezhi-Workbench-0.13.3-Portable-x64.exe` 时，测试助手连接该隔离启动实例的本机调试端口，并先核对原始 EXE 路径和隔离数据目录。此调试参数只用于测试，正常双击程序不启用。使用缓存 Playwright，可通过 `PLAYWRIGHT_MODULE` 指定本机已安装模块路径。
