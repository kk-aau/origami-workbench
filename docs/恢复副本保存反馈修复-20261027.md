# 大工程恢复副本保存反馈

## 原因与修复

旧版本在 `localStorage` 写入失败时立即显示“浏览器恢复空间不足”，随后才等待本机磁盘恢复接口。因此同一次自动保存即使已经完整写入磁盘，用户仍会收到容量告警。这条信息不是计算内存耗尽的证据。

自动恢复现在等待两份副本的实际写入结果。本机磁盘保存成功时，浏览器缓存失败不再提示需要用户处理；磁盘失败时，区分仅有临时缓存和两份副本都未保存，并清除旧的磁盘自动保存时间。真实失败写入工作日志。旧浏览器稿件保持原样，不清空、不用指针或裁剪数据替换完整工程。

写入排队、未处理恢复稿保护、原始修订号、切换工程、删除和冲突检查保留。收到异步结果后再次确认仍属于当前工程，才更新保存状态。

## 开发验证

| 检查 | 结果 |
| --- | --- |
| 恢复单测 | 18 项通过，覆盖存储分别失败、同时失败、等待中的磁盘写入及旧稿保留 |
| 旧版实机复现 | 100,004 段 CP，工程 JSON 8,256,524 字符；原生缓存配额异常、本机恢复接口成功仍误报 |
| 修复后磁盘成功 | 相同大工程触发真实缓存配额异常，磁盘写入成功后不误报 |
| 正常退出与重启 | 大工程恢复并导出完整作品，逐字段及哈希一致 |
| 真实磁盘失败 | 仅锁定隔离测试目录的恢复文件，实际接口返回 503；旧磁盘副本字节保持不变 |
| 降级反馈 | 小工程缓存成功时提示仅临时缓存；大工程两份失败时明确提示未保存，均不显示旧磁盘保存时间 |
| 故障恢复与清理 | 释放文件锁后完整落盘；29 项交互、5 次正常原生关闭通过，测试进程、端口和锁全部释放 |

证据位于本机 `output/recovery-storage-20261027/` 与 `output/recovery-qa-20261027/`。上述是独立开发实机验证，新的最终安装包、便携包仍需分别验收，不能以此代替新包测试。

自动恢复仍采用 700 毫秒防抖；尚未触发或尚未完成的写入不保证保存。恢复副本不等同于手动保存完整作品，原有未保存关闭确认仍保留。
