# 折纸工坊 · 本机工作台

本地优先的中文折纸设计工作台，包含 CP 折痕编辑、参数化镶嵌、平折分析、三维数值预览与折序绘图，支持本机文档管理、独立草稿和多种格式导入导出。

界面采用 React、TypeScript 与 Electron，本地服务使用 Node.js，部分构造计算使用 Python。当前源码版本以 `package.json` 为准，桌面发行包与源码更新记录分别维护。

## 五分钟上手

1. 直接体验默认手风琴示例，或在“工程库”新建空白纸张／水雷基础形。
2. 左侧选“线段”：单击后松开保留起点，再次点击确定终点；也可以直接按下、拖动到终点后松开。两种方式均可吸附网格、端点和交点。顶部山／谷选择控制**下一条新线**。
3. 切回“选择”，点击已有折痕，右侧“修改选中线型”会立即修改**选中对象**。可撤销，两处状态互不冒充。
4. “检查折痕”检查局部问题；“平折分析”查看完全折叠几何及受限层序结果；“三维模拟”缓慢增加目标折叠比例。
5. 在“镶嵌设计”的九类入口选择构造，先用默认参数生成预览；可切换母结构和原始—对偶参考，或编辑种子／网格／对偶后重新生成。候选检查允许采用后，点击“采用折痕副本”继续分析或手工修改；完整工程保存构造参数，可随时读取恢复。
6. 点“保存工程”写入工程库；重要作品再导出一份完整 `.zhezhi.json` 到自己选定的位置。

快捷键：V 选择、L 画线、H 平移、1 山折、2 谷折、3 未指派；Ctrl+S 保存、Ctrl+O 导入、Ctrl+Z 撤销、Ctrl+Y 重做、Delete 删除、Esc 取消。**按住滚轮直接拖动画布**，滚动滚轮缩放；空格拖动仍保留。Shift 多选／锁定画线方向。

交点实时显示为小圆点，提交绘制或移动时会**真正把相交线段分割成独立小段**，不必先执行“整理交点”。点击一小段只选择该段，改型、Delete 和右击删除也只作用于该段；直接点击交点仍会高亮该点的关联小段。新线和自动分段合并为一个撤销步骤。辅助线与纸边也会在交点处分段，山谷、目标角和未知角不丢失；边界保护仍然有效。打开旧工程时同样自动分段，不会直接覆盖原文件，确认后再保存。

### 工具提示、角平分线与右键

- 选择工具后，画布上方常驻中文用法和当前步骤；鼠标右上方的小提示跟随当前步骤，靠边时自动避让，不阻挡点击。
- 角平分线：依次点击角边点、顶点、另一边点，**再点击截止线段或纸边**。第二点是角平分线起点；终点是内角平分射线与所选有限线段的交点，不是第四次点击的鼠标坐标。前三点不会提前画出正式折痕。
- 构造参考线、候选角平分线及测量预览为紫色；确认后的正式折痕才使用当前山谷类型。选择无效截止线时保留已选三点并说明原因。
- **构造进行中右击：只取消并归零，不删线。尚未开始构造时右击：删除命中的小段；按住右键向右拖动（实线框）：仅删完整包含的小段；向左拖动（虚线框）：删除与矩形相交或接触的小段。** 按横向方向区分，纯竖向默认完整包含。删除遵守边界保护，可一次撤销；Esc 也可取消。
- 按住左键拖画或移动途中再按右键，同样取消未提交的操作，松开左键不会补提交。

## 必须知道的边界

- 几何无交叉、Kawasaki／Maekawa 通过、找到整体层序、存在连续无碰撞折法，是不同结论。界面分开报告。
- 镶嵌参数范围是**探索范围**，不是所有组合可折。错误候选会提示；尚未进行实物试折，不声称经实物验证。
- 三维模型可能自穿透、产生应变或失稳；没有可靠的碰撞、纸厚、摩擦及可制造性保证。
- 平折按完全折叠角分析，不把任意目标角静态解释为平折结果。大型复杂层序可能超时或不支持。
- FOLD 目前用于二维 CP 交换，不是任意三维、多帧、层序数据的无损编辑器；完整工作台工程请使用 `.zhezhi.json`。
- SVG 是出版线型图，不是 Origami Simulator 的颜色编码输入；跨软件计算交换优先用二维 FOLD。
- 图片自动识别、树形／方格基础形设计、高级定位教程、曲线，以及原工具的全部高级构造尚未提供。ORI／ORH 的支持范围以导入导出的损失提示为准。
- “自动恢复”仅保存最近工作，不替代手动保存和外部备份。用户已有工程不应只保留在浏览器缓存中。

## 工程保存在哪里

- `data/projects/<编号>.json`：手动保存的工程；覆盖保存时保留 `.json.bak`。
- `data/recovery.json`：最近工作恢复副本。
- 浏览器本地存储还保留恢复副本，服务写入失败时界面会提示。
- `logs/`：由启动器新启服务时写入的诊断日志，不包含主动上传机制。

如要备份，可以导出完整工程，或在没有写入操作时复制 `data` 目录。不要把 `data` 当成编译缓存删除。测试使用临时数据目录，不清理这里的真实作品。

## 从源码重建

在 `workbench` 目录，使用现有 Node.js / npm：

```powershell
npm ci
npm run build
npm test
node --test tests/server.test.mjs
```

只在 Python 私有环境缺失或迁移到新位置时重建它（已存在时不要覆盖）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests/backend -v
```

依赖安装／首次重建需要取得锁定依赖，通常需要网络；日常启动不安装它们。`.venv` 是依赖当前 Python 安装的私有环境，不是可随意复制到另一台机器的完整运行时；新机器需要重新准备。

开发模式：`npm run dev` 提供前端开发页面；本地 API 仍由 `node server.mjs` 提供。不要把开发服务器对外开放。

验证细节见 `docs/tess-validation.md`、`docs/server-validation.md` 和其余模块验证记录。现阶段交付为本机可运行源码工作台，不是经过跨机安装测试的商业发行包。
