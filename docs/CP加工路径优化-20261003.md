# CP 加工路径优化与验收

已新增工作区上方的独立「优化加工导出」入口，输出连续路径 SVG / R2000 DXF，另提供普通 LINE 结构的 R12 兼容版。原 CP、普通导出及原工程保留。未操作刻字机，未自动发布，未重新制作安装包。

同日兼容跟进：用户实际反馈旧加工 DXF 无法导入，并提供成功／失败样本。旧 R12 POLYLINE 加私有扩展方案已替换；本页测试表记录首轮历史验收，新三格式、真实样本及本次完整测试见 [兼容修复与验证](DXF刻字软件兼容修复-20261003.md)。

## 使用

1. 打开二维 CP 工程，点击「优化加工导出」。曲面原生设计没有直线 CP，入口禁用。
2. 每种线型独立选择参与加工、方式与次数。点击线型可填写工具、速度、压力标签；默认每条有效源边一次。
3. 默认线型分别成组。只有勾选「我确认：允许合并加工设置完全相同的线型」后，方式、工具、速度、压力、次数全部相同的设置才能合并。不同设置仍分组，外框没有强制最后加工规则。
4. 点击「生成预览」。优化前后均可查看路径与起点编号；虚线仅展示空走，不写入文件。设置改变会使旧预览和导出失效，需重新计算。
5. 选择 SVG、DXF R2000 连续版或 DXF R12 普通 LINE 兼容版后导出；指标与预览随格式切换，兼容版按实际独立线段计数。可另存 JSON 核验报告，含完整路径与来源映射。点击取消、Esc 或停止计算会终止后台线程，迟到结果不会恢复导出或修改工程。

速度、压力与工具是加工分组及核验标签，不向设备发送命令；实际参数由用户在刻字软件中配置。报告也不证明刻字软件会保留路径顺序或加工设置。

## 几何与优化边界

| 项目 | 行为 |
|---|---|
| 接点 | 仅连接数值完全相同的既有端点；默认不吸附、移动、翻转、缩放或数值分割 |
| 未分段交叉 | 保留整条原线独立加工；已有交点分段 CP 可在真实共享端点连续连接 |
| 断开图 | 分开路径，绝不新增跨空白落笔连接线 |
| 重复／部分重合 | 默认阻止导出并提示；仅明确勾选保留后按每条来源及次数加工重叠区域；无静默删除 |
| 零长／无效输入 | 零长明确计数且不加工；非法坐标、次数、容量或空加工集拒绝，不交付部分文件 |
| 多次加工 | 次数显式展开为实际边，回读计数；不再让文件中的次数元数据乘一遍 |
| 统计基线 | 相同所选边和设置，按原分组顺序逐边加工；空走从用户起点开始，不包含最后回原点 |
| 算法 | 各组连通分量用虚拟中心欧拉分解，再用最近邻、路径反转、闭环起点与有限 2-opt 排序；虚拟边绝不输出 |
| 退回 | 若候选空走更长，明确提示并保留原分组路径；不保证全局最短空走或始终达到路径数下限 |
| 容量 | 保留项目 12,000 段、展开加工次数最多 48,000 边限制；大图采用有界排序及后台线程 |

SVG 沿用内部毫米坐标和现有原始 viewBox，使用无填充、无虚线的连续 `M/L` 路径。DXF 两版均沿用普通 DXF 的毫米数值与一次 `Y=-y`，不再次缩放。连续版使用完整标准 R2000 / AC1015 模板与 `LWPOLYLINE`，以 `$INSUNITS=4` 声明毫米；兼容版复用普通 R12 / AC1009 的 `LINE` 结构，不加入该旧版本没有的 `INSUNITS` 字段，应按一绘图单位等于一毫米导入。兼容版仅保留优化边顺序，不能表示连续落笔，实际软件可能逐段抬笔。

序列化后独立解析真实坐标、样式、单位、位置、路径顺序、设置及每条来源的加工次数；再与原工程重新构建的预期比较，不信任来源元数据声明。加工 DXF 不再携带私有 JSON 头注释、来源 APPID 或 XDATA；使用标准图层保留加工设置分组，完整设置与来源映射放独立 JSON 核验报告。SVG 保留原有来源属性与核验行为。

## 附件复用与已有工作

最初按用户给定的 `CP_Path_Optimizer_v1.zip` 名称搜索项目及常用下载位置未找到；随后用户提供实际 `CP_Path_Optimizer_v1 (1).zip`，已只读检查并安全提取所需实现与测试。18 个选定文件与附件 SHA256 清单一致。压缩包 SHA256：`1a6e3436958252c759f59d5a09e2b82790e4784465cc80ccd6c6c22e38e1f213`。

直接移植其 `makeTrails`、`reversePath`、`rotatePath`、`orderTrails` 的可靠代码并适配本项目；保留原 MIT 声明和原 DXF 解析器，作为第二套独立几何回读。兼容修复后连续 DXF 同时复用其完整 R2000 写出模板。附件说明是实现资料，不替代当前用户要求。未接入其设备文件处理、吸附或静默去重。

项目没有 Git 元数据。修改前记录 `output/audits/cp-optimizer-baseline-1003.json`（1,499 个已有源码、测试、脚本及文档文件），修改后逐项核对；原有源码／测试只改 `src/App.tsx` 的四处入口接线，其余已有工作保持。普通 CP 的浏览器下载副本和完整工程在取消前后逐字节一致。
