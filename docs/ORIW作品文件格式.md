# ORIW 作品文件

ORIW 是 **Origami Work** 的缩写，扩展名为 **`.oriw`**。它保存当前完整折纸作品，使用带索引的分区容器。**新文件不压缩，所有分区原样存放。** MIME 为 `application/zip`；ZIP在这里仅作为分区容器，不代表使用压缩算法。

## 使用与保存范围

| 操作 | 行为 |
| --- | --- |
| 保存完整作品 | 默认保存 `.oriw` |
| 文件 → 导出完整作品 JSON | 保留 `.zhezhi-artwork.json`，便于旧版与其他工具读取 |
| 打开文件／打开完整作品 | 同时支持 ORIW 与旧完整作品 JSON |
| 本地文档库、草稿、恢复副本 | 保持原有 JSON；不会因本次更新批量改写 |

保存范围与原完整作品相同：当前折痕、基础形设计、构造参数、模型集合、当前折序及三维姿态。各工作区的独立来源保持独立。完整作品不包含整个本地文档库，也不将独立文档标记为已保存。撤销历史与需要重新分析的层序信息沿用原导出规则。

## 容器版本 1

使用单卷 ZIP32，固定包含以下七个普通文件。索引必须为第一个文件。**全部条目统一使用 STORED（方法0），写入不调用DEFLATE。** 读取器兼容已有DEFLATE条目。

| 条目 | 内容 |
| --- | --- |
| `manifest.json` | `format: "oriw"`、容器版本、原作品版本、各分区路径／UTF-8字节数／CRC32、作品摘要 |
| `editor.json` | 当前折痕文档 |
| `models.json` | 模型集合及各自来源 |
| `diagram.json` | 当前折序工程及独立CP状态 |
| `simulation.json` | 三维来源、姿态、固定点与视图 |
| `construction.json` | 镶嵌与曲面构造参数 |
| `design.json` | 基础形设计；原作品版本1使用null占位，解码时不注入design字段 |

容器版本与作品JSON版本分别管理。当前读取原作品版本1和2；版本2的显式`design: null`与版本1缺少design字段保持区分。

正文仍采用UTF-8 JSON，不做浮点量化、几何去重或任意metadata引用替换。未知metadata、Unicode、特殊属性名及合法空值按原数据保留。索引仅用于描述分区，不能作为几何或拓扑已验证的凭据。

## 校验与执行位置

| 阶段 | 要求 |
| --- | --- |
| 保存线程 | 先执行原完整作品导出校验，再编码分区与ZIP；返回只读Blob |
| ZIP预检 | 核对中央目录与本地记录、方法／标志、文件范围、固定路径；拒绝重复、缺失、额外条目、重叠、加密、分卷、ZIP64及不支持的扩展 |
| 读取分区 | 分块核对实际长度、CRC32和UTF-8，不按未经信任的声明长度预分配整块输出；兼容读取DEFLATE时仍核对压缩数据完整结束 |
| 作品准备 | 组装原JSON信封，执行原完整作品、几何与拓扑验证，以及CP规范化 |
| 发布到界面 | 使用现有ACK分批传输，全部准备完成后才恢复工作区；取消、损坏或失败保留原作品 |
| 桌面写盘 | 复用Rust原生保存对话框、分块写入和原子提交；宿主确认后才报告保存成功 |

当前全部分区仍需在打开时完成校验，并非增量保存或仅加载活动分区。新格式为内容分区提供明确索引，避免压缩和解压的额外开销；后台准备与列表缓存解决界面阻塞问题。文件体积与原JSON接近，并增加少量索引与容器头开销。

源码入口：`src/app/artworkArchive.ts`、`artworkZipIntegrity.ts`、`artworkSerializationTask.ts`，以及对应保存／导入Worker。回归与真实样本体积记录位于`output/artwork-format-20261112/`。
