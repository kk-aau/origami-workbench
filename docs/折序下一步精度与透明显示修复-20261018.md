# 折序“下一步”精度报错与透明显示

2026-10-18，源码更新。本轮未生成桌面发行包，未修改用户提供的工程或日志原件。

## 实际问题与根因

用户在折序绘图画线后点击“下一步”，提示“纸面修形的变换精度不足，无法可靠映射折痕”。收到的工程包含 23 步；用原始保存数据可以复现第 19～23 步的映射错误。

| 证据 | 结论 |
|---|---|
| 第 23 步出错纸面外边界的等距检查通过 | 不能据提示认定用户拖动过纸角或把纸面拉坏 |
| 局部分区出现近共线三角形，并纳入属于其他纸面的同直线顶点 | 三角形分区错误；错误顶点带来 37.5 mm 的位置偏差 |
| 错误分区使变换系数和偏移量极大，回投残差达 0.25 mm | 精度校验拒绝结果，属于程序错误而非应放宽校验的正常误差 |
| 第 23 步真实纸面最小支撑宽约 3.38 mm，出错纸面宽 6.25 mm | 工程的真实纸面并不细小；应清理数值细屑，而不是删除实际纸面 |

此前局部三角形只用“面积大于坐标容差的平方”过滤。长而近共线的三角形仍可能通过；后续插入其他展开折痕端点时，退化区域错误扩大到纸面外。

修复改为用局部坐标叉积和最长边检查最小高度，移除高度不超过原坐标容差的三角形。原有坐标容差、仿射回投检查、退化及自交保护均保留。修改只作用于绘图分区缓存，不修改原 CP、纸面编号、模型坐标或求解器拓扑。

## 第 23 步为何透明

对该步保存的现有几何独立重分析，求解器返回 `solved`、48 个候选和 876 条局部上下关系，但没有可供整个模型使用的统一绘制顺序；该步也没有保存的手动遮挡顺序，且“透视”关闭。

因此，该模型仍按现有规则透明预览。此结果不等同于“没有层序解”，也不证明原 CP 的等距压平或连续折叠路径一定可行。界面现在显示“局部层序已确认 · 未取得统一绘制顺序 · 透明预览”，将这种情况与全局层序确认及主动“透视”区分。

工程快照载入时会清除旧层序证书，并统一标记为导入几何；不能仅从导出文件中的 `modified` 或 `unknown` 判断用户是否修形、或截图时求解是否成功。

## 工作日志

用户提供的 287 条日志没有记录下一步映射、模型计算和联动停用的具体阶段，无法据其确定第 19 步联动关闭是手动操作还是失败后自动停用。新增以下诊断事件，记录阶段、步号或数量、状态及失败原因，不记录工程正文或完整路径。

| 事件 | 内容 |
|---|---|
| `diagram.next.start/success/error/wait` | 切换前校验、进入步骤、失败位置、等待固定侧 |
| `diagram.compute.start/success/result/error` | 几何计算或层序重分析；几何失败、CP 同步失败及联动停用原因 |
| `diagram.layers.start/success/result/error` | 自动层序分析、是否取得统一绘制顺序、无解或超时等未确认状态 |

层序无解、超时或错误按实际状态记录，不记作求解成功；几何生成与层序求解仍保留各自的阶段和状态。
