In[3081] 的 `src/app/p36In3081Source.ts` 固定保存的 13 个 `{边数,旧片,旧边起点,新边终点}` 条目，并用当前可检验的 `embedTilingSpecs` 和 `assembleTiles` 构造母图；工作区“自定义”区域提供“十三块 · In[3081]”按钮。载入后可通过“编辑逐块褶宽、褶角与山谷”调整每块参数；改动后是本地变体。`tileSpecs` 作为本地来源几何记录，经工程读取验证；提交后端时按当前通用管线剥离，仅发送实际母图及逐块参数。

In[3087] 在“自定义 → 原版正多边形 → 逐块偏置 → 拼块排布”提供“四方编织 · In[3087]”。`unitRegularCentered.arrangement='in3087-four'` 要求四个正方形及逐块参数一致；工程读取重新比对顶点、面与扭转参数，来源几何或山谷被单独改动会拒绝。调整 `w`、各块 `d` 或 M/V 后仍使用保存接边形状，但属于本地变体，须重新通过整片门禁。

In[3088] 的源定义 `RenderTile[QuadrilateralOffsetSplitTwistTile,…,TGraphAssigned]` 在约 221238–221250 行明确将 `d>0` 传给普通分裂构造的方向参数。**分裂基点须按各片原始逆时针顶点顺序编号**；先将母图面反向再沿用 `ip` 会虚假触发“分裂校正交叉”。保持来源顺序时四块各自可构造、整片几何及 Kawasaki／Maekawa 均通过，二维逐面反射闭合误差约 `2.56×10⁻¹⁰`。然而现有产品层序约束传播返回 `no-solution`。

专项测试给出可机验的最小冲突：在本项目重建的平折图中，8、9、11 号面有**正面积三重重叠**（画布坐标约 `23.2739` 平方单位）。以 0 号面为锚点，相邻折线预置 `8↔9=2`，只传播 taco/tortilla 局部约束便推出 `8↔11=1`、`9↔11=2`；按三面环 `8→9→11→8` 统一方向换算即 `2,2,2`，违反三面层序传递性。完整约束在搜索分支前报 `invalid transitivity`。换用 16 号锚点时环向全部翻成 `1,1,1`，仍不满足传递性；产品默认锚点也返回 `no-solution`。测试独立计算三重交面积、局部推论及完整传递性错误，未删约束来伪造可采用结果。
