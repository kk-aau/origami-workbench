# 大工程精确平折与显示验证

本次修改仅位于独立 Tauri 工程。原 `workbench/` 与已发布应用包未改动，本文不构成发布验收记录。

## 计算规则

| 环节 | 实现与边界 |
| --- | --- |
| 手动平折、层序重算、遮挡 | 默认不限时间、面数和搜索节点数；用户停止时直接终止 Worker。计算耗时不能单独作为死循环依据。 |
| 大型默认候选 | 至少 256 个凸面、未指定解编号或可见面约束、未请求升降/继承偏好时，求一个通过全部实际覆盖区域验证的候选。 |
| 编号解、可见面约束、升降纸层 | 保留原有求解及编号语义。显示分析只验证当前选中解，不擅自换解或补猜测关系。 |
| 自动预览 | 调用方主动设置的有限预算仍有效，与手动完整计算分开。 |
| 完成判定 | 所有真实区域的层序、轮廓和请求的正反面/阴影均验证后才发布完整纸面。异常、无解和取消如实返回。 |

## 共用精确分区

1. 将公开折后 IEEE 浮点坐标表示为精确有理数；构造交点、半边邻接、连通分量和孔洞。不得用显示容差合并真实微小区域。
2. 只存紧凑拓扑，遍历时增量更新当前覆盖纸面；不常驻保存近三亿条重复的区域—纸面关系。
3. 接触约束仍沿用现有求解器。将全部实际共覆盖纸面对加入候选，逐区检查完整有向比较是否无环；遇到真实三环才追加必要约束并重新求解。
4. 每次最多收集一万条反例只是批次大小，不是完成上限。必须全量遍历且零冲突才生成逐区顶部、底部和深度证书。
5. 正反面和阴影共用这份证书与拓扑，合并同一顶部原纸面的内部边。只把可见轮廓传给主线程；不为合并后的纸面伪造旧式区域或纸层数组。

有限 F 折痕使用私有面积轮廓求接触约束时，覆盖认证仍针对公开材料几何，不将私有轮廓证书直接冒充公开几何证书。

这里的“精确”针对程序实际保存的折后坐标与区域关系，不等同于证明理想纸张的精确刚性折叠、连续无碰撞路径或有厚度纸张的可制造性。

## 缓存和显示

- 精确拓扑与证书仅驻留计算线程的 WeakMap，计算后释放，不写入工程、撤销历史或源码归档。
- 主线程只缓存完整可见轮廓。模型历史、相同快照副本和导出可复用；几何、层序关系、解编号、约束或绘制顺序改变后失效，包括原位修改。
- 正反面、双/四视图、导出和镶嵌装饰采用明确的精确纸面分支。保留原始 F 编号、选择身份、孔洞及断连轮廓。
- 阴影只在同一精确来源线、相同上下层/裁剪/方向、共享真实顶点且连续时合并显示；全部原始阴影段仍保留。当前旋转/镜像投影下，经 56,000 个采样点比较渐变和孔洞裁剪一致。
- 大量源顶点的范围计算使用循环，避免 JavaScript 函数参数展开栈溢出；20 万顶点回归通过。相机更新复用已验证状态，不重复扫描可见边界。
- CP 缩放和平移的 GPU 绘制与精确层序求解分别处理。GPU 绘制加速不代替 CPU 的精确拓扑和层序认证。

## 实际浏览器线程与主图

Windows Edge 在普通堆限制下调用生产计算 Worker，从同一份已整理 CP 重新生成几何并计算至完整双面纸面，耗时 **834.311 秒**，渲染进程峰值工作集 **2731 MiB**。手动取消另一次真实任务的响应为 **21 毫秒**。未安装或配置额外大堆运行时。

本次实际线程得到 1,827,830 个区域、3,662,938 条关系，两面全部验证通过。它与上述缓存几何实验的面/边/山谷指派相同，但重新生成的顶点坐标最大差约 5.98×10⁻¹³；精确分区数量因此略有差异。两次认证各自绑定实际几何，未互换证书。
