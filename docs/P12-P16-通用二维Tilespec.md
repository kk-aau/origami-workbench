# 第 33 节：二维 tilespec 与 JoinTiling

原版 `Origamica 15.0.nb` 第 33 节 In[2802]–In[2812] 将每块写成 `{tiletype, offset, rotation, scale}`，以 `offset + RotationMatrix2D[rotation] . (scale * point)` 嵌入。`EmbedTiling` 按输入顺序渲染，并可将 `TileIndex` 传到每块。保存的 In[2811]/Out[2811] 中，两个 `{TestTile,4}` 的位移分别为 `{0,0}` 与 `{1,0}`；输出的四角分别为 `(0,0),(1,0),(1,1),(0,1)` 与 `(1,0),(2,0),(2,1),(1,1)`，中心编号落在 `(0.5,0.5)` 与 `(1.5,0.5)`。

工作区“自定义 → 拼块组合 → 原版 tilespec / JoinTiling”可对已有的数值多边形拼块逐块设置绝对位移、角度和倍率。打开时以每块原有第 1 点作局部原点，因此初始画面与已有几何完全一致。编辑器即时显示轮廓、拼块编号与逐顶点编号，并显示求得的实际位移、角度和倍率。采用后将数值几何及经严格回读的原始 tilespec 参数写回拼块组合，仍须通过整片共边连通、无重叠及顶点上限校验。

原版 In[2816] 的 `JoinTiling` 使用 1 起始的 `{i,j,k}` 引用。本界面的 `+k` 使本块点 `k` 对齐目标块点 `j`，并求旋转与倍率，使本块前一点 `k−1` 对齐目标块下一点 `j+1`；`−k` 仅使两点对齐，保留输入角度与倍率。可再加入 `{x,y}` 附加位移，预览原版的“爆炸”排布；若因此断开共边，画面仍能预览，但不会被当作可采用的纸面。脚本中的索引用 0 起始，界面显示用 1 起始。

专项回归以 Out[2811] 的确切四角为锚点，另覆盖 90°／2 倍绝对嵌入、`+k` 共边、`−k` 单点、附加位移、引用错误，以及结果经过工程参数 JSON 保存读取后的坐标。浏览器在 1000×720 下实测：原始四块 0.5 单位方格中，第 2 块的局部方格设绝对位移 `(1,0)`、旋转 `0°`、倍率 `2`，实时预览四角精确为 Out[2811] 第 2 块的 `(1,0),(2,0),(2,1),(1,1)`。还原后改设 `+k`、目标块 1、目标点 4、本块点 1，预览得 `(0,0.5),(-0.5,0.5),(-0.5,0),(0,0)`；采用、保存拼块组合并重新打开后仍是同一组四角，弹窗没有内部滚动或脚本错误。

此入口支持现有母结构的数值二维 `PolygonTile`，以及三内角来源的稳定 `UnitTriangleTile`、边数来源的 `UnitRegularPolygonTile`；工程同时保存数值几何和来源参数，回读时重算嵌入后的每个索引顶点及面。正多边形来源的原版公式和边数编辑验收见[第 33 节专项](Origamica第33节单位正多边形TileSpec-20260927.md)。顶点／拼块编号在本弹窗属于即时 `Tiling` 预览；持久化的填充、边箭头、中心标签及折痕／平折叠加仍由旁边的“拼块装饰”入口设置。任意 Mathematica 符号 `tiletype` 及表达式求值不在此数值入口内。原版没有具名镶嵌拼块的 3D `TGraph3DAssigned` 专用分派和保存输出，因此本入口不提供臆造的 Graphics3D／TObj 拼块装饰；真实非平面构造按独立保存例处理。

## 2026-09-27：`UnitTriangleTile` 具名母拼块

笔记本 224942–225045 行的 In[3020]–In[3022] 定义 `{UnitTriangleTile, angles}`，并把所有装饰委托给 `PolygonTile[UnitTriangleVertices[angles]]`；保存的 `Tiling` 输入为角度 `{50°,60°,70°}`。以第一边为单位水平边，第三顶点由正弦定理重建为 `(sin60°/sin70°·cos50°, sin60°/sin70°·sin50°)=(0.5923962654520477,0.7059903775918711)`。这是原版公式推算，不是笔记本保存的数值 `Out`。

`src/app/tileSpecs.ts` 现在保留 `tiletype='UnitTriangleTile'`、三个内角和由其推得的单位顶点；回读拒绝内角和错误、非单位顶点、额外表达式与失效的拼块引用。界面仅能将已有逆时针三角形转换为该具名类型，编辑前两角、自动求第三角；不把任意非三角形改写为原版三角类型。转换时角点几何与旧双三角 In[3028] 相差约 `10^-16`，仍属同一索引网格；`changeTessParams` 用与来源回读一致的 `10^-8` 坐标容差保留原 `w=.1、α=25°、MMM/VVV` 逐块扭转参数。真实顶点移动或面索引改变继续重置这些失效参数。

`tests/app/tileSpecs.test.ts` 的 12 项专项均通过，覆盖保存例公式、共边对接、项目回读、伪造拒绝和几何同一性两侧。1000×720 独立浏览器中，In[3028] 原版双块在首块转为 `UnitTriangleTile` 后 `/api/tessellate` 返回 200，仍为 2 单元／28 边且层序已解；切换 `Tiling` 母结构也返回 200，重新打开来源仍读得 50°／60°，双层弹窗的高度分别为 601/601 和 578/578，无纵向滚动。该来源标签不额外证明所有角度组合均可平折。

## 2026-09-27：In[3182] 异构 3.3.3.4.4 单补片来源

原版笔记本 In[3124–3126] 的 `ArchimedeanPatch[6]` 以两个单位正三角形和一个单位正方形组成三片补片，按 1 起始引用 `{1,2,1}`、`{2,2,2}` 共边对接；In[3182] 在同一三片上保存 `w=.2、α=25°、MMM/VVV/MMMM` 的居中 Alt 输入。先前工作区能生成该 CP/FF，但在拼块组合弹窗打开时三片仅显示数值 `PolygonTile`，没有逐片保留原版 `UnitRegularPolygonTile(3/3/4)` 和两次 `JoinTiling` 来源。

现在只有当前三片的索引顶点与保存补片在 `10^-8` 内逐点吻合时，tilespec 弹窗才显示“套用 3.3.3.4.4 来源”。采用后保存三条具名来源及 0 起始的 `{目标块,目标点,本块点}` 为 `{0,1,0}`、`{1,1,1}`。用户若只改变来源而不改网格、周期和输出，拼块组合保存时只提交 `tileSpecs`，因此原 `archimedeanPatch` 及三块扭转参数仍保留；真实改动几何时继续执行来源失效清理。严格回读重算所有单位顶点、两次共边连接和完整网格，伪造第二块引用或顶点会被拒绝。

`tests/app/tileSpecs.test.ts` 验证来源、边引用、几何同一性、扭转参数保留及工程 JSON 回读。`npx tsx scripts/verify-tilespec-patch6-in3182.ts` 从保留来源的工作区参数经真实后端和平折层序流程，得到 CP 32 点/48 边/17 面、几何与局部条件通过、平折几何 `ready`、面内距离最大误差 `1.37×10^-7`、层序 `solved` 且精确 1 解、正背各 520 个局部区域全有序。`tileSpecs` 是经过网格身份核验的来源元数据，不改变构造键或 CP 数值；结果仍限于**单个补片**，不能外推到周期复制的 Alt 扭转。笔记本没有此例可机读的 CP/FF 数值 `Out`，上述计数和误差均为本项目本地推演，不是 Wolfram 逐点对照。
