# 第 37 节双三角 2×2 接缝：In[3106] 与 In[3180] 的保存输入组合

原笔记本 `tmp/Origamica-15.0-reference.nb` 的 In[3106]（231915–231972 行）保存了 `ArchimedeanPatch[1]` 经 `ArchimedeanPatchLatticeVectors[1]` 和 `MakeLatticeTiling[...,{0,1},{0,1}]` 产生的 2×2 母格。In[3180]（234488–234566 行）**另行**保存了同一双三角来源补片的 `UnitRegularPolygonCenteredTwistPatch`：宽度 `w=0.2`、褶角 `τ=70°`、逐边山谷 `{{M,M,M},{V,V,V}}`。笔记本没有保存“先 In[3106] 复制，再对八个片应用 In[3180] 配方”的数值 `Out`，故该组合是按两个明确保存输入重建的可验证子域，不称原版已有的 2×2 折痕样例。

本项目入口为普通阿基米德 n=1 的“**双三角 2×2 扭转 · In[3106]+In[3180]**”。来源片为顶点 `(0,0),(1,0),(.5,√3/2)` 与 `(1,0),(1.5,√3/2),(.5,√3/2)`，格矢 `(1,0),(.5,√3/2)`。展开顺序是 `j2` 外循环、`j1` 内循环，再按来源面 0／1：`(0,0)`、`(1,0)`、`(0,1)`、`(1,1)` 各两个三角片。每个来源面重复同一 `w,τ,M/V` 配方，经现有逐块构造与共边合并产生真实整片 CP，不把独立单片的折后画面简单复制四份。

| 核验项 | 结果 |
| --- | --- |
| 8 来源片接缝 CP | 64 点／96 边／33 面；M36、V36、边界 B24；共边合并为 `delete` |
| 来源与通用分派 | `construct_tile_patch` 直接来源构造与工作区 `custom` 请求的边、赋型、折角、面及来源面一致；顶点最大差小于 `10⁻⁹` |
| 几何和平折 | 几何及局部条件通过；整片反射闭合误差小于 `10⁻⁸`，每个面任意两顶点的展开／折后距离差小于 `10⁻⁸` |
| 工作区层序与显示 | `computeFlatGeometry` 为 `ready`；`recomputeFlatLayers` 精确 1 解；正背面各 1197 个局部覆盖区域均有序 |
| 工程保存读取 | `in3180-centered-lattice2x2` 来源记录可通过 JSON 回读；改动范围、格矢、褶角、M/V 或构造选项会拒绝冒用该来源 |

验证入口：`backend/test_tessellation_archimedean_patch1_lattice_in3106_3180.py` 用解析源顶点与四格顺序核对原版输入，再独立比较直构与通用服务的 CP、共边和面内等距；`tests/app/archimedeanPatchSource.test.ts` 核验预设及来源回读；`scripts/verify-archimedean-patch1-lattice-in3106-3180.ts` 从工作区预设直接生成 CP，运行平折几何、全局层序和正背区域门禁。该脚本已加入 `npm run test:tessellation`。

边界：此结果不证明 Mathematica 未保存的组合输出逐点等价，也不证明连续运动路径或纸张厚度下的制造性。它不能外推到 `ArchimedeanPatch[6]` 的 In[3182]：其保存例是**单个三面补片**的中心扭角 Alt 构造，`w=0.2, α=25°`、M3/V3/M4；直接按同配方复制成 2×2 时，当前本项目接缝的局部山谷赋型无法满足约束，因此继续只标注单补片已验，不将本组合冒充 In[3182] 周期 Alt 的复现。
