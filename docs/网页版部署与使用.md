# 浏览器版 · GitHub Pages

在线入口：https://kk-aau.github.io/origami-workbench/

这是现有工作台的独立浏览器构建。计算在访问者浏览器内进行，工程不上传服务器，桌面版仍保留完整本机计算能力。

| 功能 | 网页版 |
| --- | --- |
| 折痕编辑、CP 导入导出、平折与层序计算 | 使用现有前端和 Worker |
| 折序绘图、三维模拟、步骤和全程动画 | 使用现有前端与 WebGL；复杂工程受访问者设备性能影响 |
| 工程库、草稿、恢复记录 | IndexedDB；同一浏览器同时使用一个工作台标签页 |
| 文件导出 | 浏览器下载；请确认文件已保存到本机 |
| PDF | 页面以 300 dpi 无损图像写入 PDF；需要矢量 CP 时选择 SVG |
| 基础形设计、镶嵌和依赖本机引擎的高级构造 | 使用桌面版；网页不会将缺失引擎伪装成计算成功 |

请使用支持 WebGL2、IndexedDB 和 Web Locks 的现代桌面浏览器。打开文件通过浏览器文件选择器；网页版不能直接读写桌面工程目录。浏览器缓存清理、无痕窗口关闭或换浏览器不会迁移文档，务必下载完整作品或折序工程备份。

保存回执等待数据库事务提交；修订冲突或写入失败不会覆盖旧记录。遇到保存错误，应先下载当前工程备份，再重新打开工作台。关闭待保存页面时有离开提示，强制结束浏览器仍可能丢失尚未提交的操作。

## 构建与部署

使用 Node.js 24 和锁定的 npm 依赖，无需安装 Rust、Python 或桌面计算引擎：

```sh
npm ci
npm run build:web
```

产物为 `build/web/`，资源基路径为 `/origami-workbench/`。用静态服务器挂载到该路径；不要直接双击 HTML 或运行桌面 HTTP 服务来代替验证静态部署。

将 `build/web/` 内容发布到 `gh-pages` 分支根目录，在 GitHub Pages 中选择该分支的 `/`。`.nojekyll`、`legal/` 和 `origami-web-source.zip` 必须保留。每次源码变更重新构建；无需重打桌面安装包。不同仓库名或自定义域名需同步修改 `vite.config.ts` 的网页资源基路径。

`origami-web-source.zip` 与页面同次生成，包含网页源码、模拟器及 CP 构造源码、捆绑前端包的源码和许可、锁文件及构建说明；`legal/SOURCE-AVAILABILITY.json` 记录真实字节数与 SHA256。桌面完整源码仍在相应桌面 Release 中提供。

## 隔离验收

`tests/browser/webStorageHarness.html` 是开发环境的存储回归入口，不进入生产网站。运行 `vite --mode web`，在独立浏览器 profile 访问 `/origami-workbench/tests/browser/webStorageHarness.html`；显示通过后访问同路径 `?reopen`。覆盖真实数据库和保存 Worker、冲突、删除后迟到保存、超过 localStorage 大小的内容、事务故障回滚及刷新恢复。它主动模拟存储失败，不能在日常使用的浏览器资料中运行。

生产验收另用纯静态服务器验证 CP 导入、保存、平折、三维、折序动画与 PDF/SVG/PNG 下载，再在实际 Pages 地址检查同样的资源路径。页面不能依赖 `/api` 服务。
