# Origamica 第 37 节：ArchimedeanPatch[8] 非方格周期与 Alt 审计

本次选择原版 `tmp/Origamica-15.0-reference.nb` 的 `ArchimedeanPatch[8]`，顶点构型为 **3.4.6.4**。它比已核的 n=6 更复杂：一个来源单元含三正方形、两正三角形、一正六边形；原版又保存了 2×2 平铺、双色奇偶和带负格点的 Alt 扭转。原版相关 `In[3132–3134]`、`In[3164]`、`In[3186]` 只有定义、`Print` 与图形调用，没有可机比的数值 `Out`、CP 点表或全局层序证书。以下几何锚点来自源公式独立重建，不能称作原版逐点输出复现。

`In[3132]`（232895–232951 行）的 `JoinTiling` 从单位正方形开始，依次添加 `{3,{1,1,3}}`、`{4,{2,1,1}}`、`{3,{3,2,1}}`、`{4,{4,2,1}}`、`{6,{1,2,1}}`，其中三元组为 `{旧片号,旧边起点号,新边终点号}`，边反向重合。令 `h=√3/2`，由 `UnitRegularPolygonVertex` 的首点原点、首边单位水平线，得到来源面顶点如下；面内保留原片起点及逆时针顺序。

| 原片号 | 顶点 |
| --- | --- |
| 1 正方形 | `(0,0),(1,0),(1,1),(0,1)` |
| 2 三角形 | `(1/2,-h),(1,0),(0,0)` |
| 3 正方形 | `(1/2,-h),(1/2+h,-h-1/2),(1+h,-1/2),(1,0)` |
| 4 三角形 | `(1/2+h,-h-1/2),(3/2+h,-h-1/2),(1+h,-1/2)` |
| 5 正方形 | `(3/2+h,-h-1/2),(3/2+2h,-h),(1+2h,0),(1+h,-1/2)` |
| 6 六边形 | `(1,0),(1+h,-1/2),(1+2h,0),(1+2h,1),(1+h,3/2),(1,1)` |

单元内部的七对共享边来源片号为 `(1,2),(1,6),(2,3),(3,4),(3,6),(4,5),(5,6)`，外边 10 条；母结构为 12 顶点、17 边、6 面，连续且欧拉数为 1。`In[3133]`（232953–232984 行）分别取 `PatchVector[patch,{1,4},{6,4}]` 和 `PatchVector[patch,{4,1},{6,4}]`，得到 **`u=(1+√3,0)`，`v=((1+√3)/2,(3+√3)/2)`**。两向量不正交；行列式 `3+2√3` 与三方、两三角及一六边形面积之和相等。

`In[3134]`（232993–233050 行）以 `j1,j2∈[0,1]` 生成 2×2 纯平铺。当前 `family=custom/customOutput=tiling` 通用链路复跑为 **24 面、37 顶点、60 边**，几何检查通过，来源片号每格为 `[0,1,2,3,4,5]`，格点按 `j2` 外层、`j1` 内层依次 `(0,0),(1,0),(0,1),(1,1)`。24 个多边形的每个顶点都与独立来源面加 `j1·u+j2·v` 的公式相同。`In[3164]`（233948–233969 行）还指定同一 n=8 几何的双色奇偶 `[+1,-1,+1,-1,+1,-1]`；测试核对此长度和取值，**奇偶并非下述居中 Alt 的输入**。

`In[3186]`（235050–235197 行）保存 `w=.12、α=29°`、六片边类型 `M4/V3/M4/V3/M4/V6`，先按 `j1∈[-2,2]、j2∈[-1,2]` 扩展，随后用 `(0.1,0.1)–(3.9,3.9)` 矩形修剪，再调用 `MonolithicTGraph2D`。对**未扭转的来源轮廓**按同一负格点范围扩展，当前通用链路得到 **120 面、150 顶点、269 边**，来源片号、格点次序和位移逐项符合原公式，母结构几何检查通过。这一结果不包含扭转、修剪或折后图。

可受限核验的是 In[3186] 的**单个六片来源 patch**：`τ=atan(tan29°/.12)≈77.784779721°`，按原版单元类型做居中 Alt 扭转，取原版整体嵌入常用的删除共享边、共线清理设置，得到工作区 CP **54 顶点、88 边、35 面**，其中边赋型 `B30/M29/V29`。几何与局部条件通过；独立逐面反射的 FF 闭合误差约 `3.52×10^-9`，各面顶点对距离保持。`scripts/verify-archimedean-patch8-alt-in3186.ts` 从源码接边公式直接构造具名 CP，再把独立解析的顶点、面和 `α=29°` 输入 `readTessParams → tessellate.py`：两侧顶点坐标误差为 0，边、赋型、折角、面及来源片号逐项相同。这仅证明**本项目具名直构与通用请求的 CP 身份**，原版未保存可比数值 CP。

同一单 patch CP 经 `tessFlatInput → computeFlatGeometry → recomputeFlatLayers` 得到 `flatGeometry=ready`、`layerOrder=solved`、**精确 1 解**。展开与折后图的第 **9、30 面**（从 0 起）仍是显著凹面；内部 76 个三角片只生成约束，公开输出保持 35 个原面与 147 条原面关系，正背面各 1349 个局部覆盖区域全部有序。该例实际使用 147 个原面对变量、880 条去重 CNF 子句，单位传播在 1 个搜索节点得到完整唯一解。受限层序容量提高到 36 原面／80 三角片／160 原面对，子句与节点上限仍为 2048／50,000；超限继续明确 `unsupported` 或 `unknown`，不产生伪解数。四种原面起点与 `ε=10^-6、10^-7、10^-8` 的 12 次求解得到同一原面关系；独立扇形、SAT 编码及回代约束也得到同一唯一解。原版的**120 片扭转后修剪**流程仍不能由当前逐块 CP 适配器原样核验：它在展开前限制至 36 片，且本专项没有证明修剪后的来源面与原版单体图同一。不能把单 patch 解外推到 120 片修剪后图、可见面或周期整体，也不能据此证明连续无碰撞折叠路径。

回归位于 `backend/test_tessellation_archimedean_patch8_lattice.py` 与上述 TS 脚本。从 `workbench/backend` 运行 `..\.venv\Scripts\python.exe -m unittest test_tessellation_archimedean_patch8_lattice -v`；从 `workbench` 运行 `npx tsx scripts/verify-archimedean-patch8-alt-in3186.ts`。本专项未修改共享前端、`package.json` 或格点核心。第 37 节其余 `ArchimedeanPatch` 编号，尤其 n=7、9–12 的混合多边形接边、格矢及保存扭转例，未由本专项逐点核验；n=8 完整负格点扭转后的修剪与单体折后图仍是明确未覆盖范围。
