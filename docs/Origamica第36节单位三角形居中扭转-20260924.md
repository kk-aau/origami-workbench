# Origamica 第 36 节：单位三角形居中扭转具名子型（2026-09-24）

原笔记本 `tmp/Origamica-15.0-reference.nb` 的 `UnitTriangleVertices`（20335–20373 行，In[366]）将底边定为 `(0,0)→(1,0)`，令左、右底角为 `A,B`，顶角 `C=180°−A−B`，第三顶点为 `sin(B)/sin(C)·(cos A,sin A)`。原函数只取前两个角；本独立具名 API 接受 2 或 3 个角，若给出第三角则要求它与推导值一致（绝对误差不超过 `1e−8°`），且三个内角均至少 `1°`。这是为了拒绝含糊的保存参数而增加的输入约束，并非宣称原 Wolfram 函数会拒绝不一致的第三角。

原版 `RenderTile` 的 In[3024]（225221–225230 行）把 `{UnitTriangleCenteredTwistTile,angles,w,τ,types}` 交给 `PolygonCenteredTwistTile`；In[3027]（225473–225482 行）把 Alt 的扭角 `α` 交给 `PolygonCenteredTwistAltTile`。后者的 In[2905]（214878–214889 行）使用 `CenteredTwistTiltAngle[w,α]`，In[2890]（213853–213861 行）给出 `τ=atan(tan α / w)`。保存的 `α=25°` 为锐角，无反正切分支歧义；本模块把 Alt 限在 `1°≤α<90°`，用稳定的 `atan2(sin α,w cos α)` 计算同一角。两种形式沿用通用构造器的 `0.05≤w≤0.8` 和 `1°≤τ≤179°` 约束；几何可能进一步拒绝中心交点越界的输入。两个具名函数分别保留源类型、角度列表、宽度、逐条中心边 `M/V` 和原始角度字段；几何与 M/V 由已有 `polygon_pleat_tile` 构造。它们仍返回 `layerOrder=not_checked`、`adoptable=False`，因为独立模块没有执行前端整片层序求解。

上述点、边、面计数和坐标是本项目计算结果；原笔记本只保存了 Tiling、CreasePattern 与 FoldedForm2D 图，没有可直接比较的图元数表或折后顶点表。因此此处只证明原版单位三角形公式、保存参数和委托关系所确定的受限构造，以及本项目的 CP/FF 检查结果，**不声称与 Wolfram 图形逐点等价**。特别是 In[3025] 的原版 FF 图仅能说明它绘出了折后展示；在当前引擎、当前 M/V 和整片遮挡约束下，该 CP 没有一致的全局层序，不能作为可采用拼块。`no-solution` 是对本项目求解模型与该具体输入的结论，不是对所有三角形居中扭转的数学不可能性证明。In[3028] 的 `solved` 也只证明这组输入在当前约束下有一组全局层序，不证明连续无碰撞折叠路径。

双块专项测试逐边核对中心 `M/V`、边上的 `.45/.55` 宽度端点与褶角，整片 CP 的交叉和局部平折条件、各 FF 面内部所有顶点对的距离及反射闭合误差。完整层序脚本从 `.venv` 调用 `tessellate.py`，经 `prepareTessResult → tessFlatInput → computeFlatGeometry(graph,1e−6,{startingFace:tessFlatRoot(graph)}) → recomputeFlatLayers` 得到上表的求解结果。复现命令：从 `workbench` 运行 `.venv\Scripts\python.exe -m unittest discover -s backend -p test_tessellation_unit_triangle_centered.py` 和 `node_modules\.bin\tsx.cmd scripts\verify-unit-triangle-centered-in3025-3028.ts`。
