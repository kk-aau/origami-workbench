# R2000 实物边界相对内部折痕偏移

用户反馈普通 DXF 正常，R2000 优化 DXF 的实物有误差，进一步描述内部折痕似乎正确、纸张边界相对内部偏移。当前未取得本次实际出错的 R2000 文件、同源普通 DXF 和刻字软件名称，也未确认外框是压痕还是切割、偏移是否在导入预览中已存在。因此本次是已验证的软件默认策略调整，不能宣称已确认实机根因或修复实物误差。

## 查到的差异与改动

| 项目 | 旧默认 | 新默认 |
| --- | --- | --- |
| UI 路径方式 | 欧拉连续路径，可连续转弯、反转原线方向、换闭环起点 | 逐条完整源边，不合并、不反向，仅排序空走 |
| UI 文件格式 | SVG，用户可选 R2000 多段线 | R12 独立 LINE，与普通导出的实体结构一致 |
| 连续功能 | 默认参与 | 明确勾选才参与，保留原连续算法 |
| 提示与报告 | 文件几何通过，机器未验证 | 另展示实际文件的连续转向数及原线反向数；明确几何通过不等于实机精度通过 |
| 外框与内线 | 共用一次 Y 反射 | 保留同一坐标系；增加不居中外框的逐层对照及仅外框平移的拒绝测试 |

默认 R12 在未合并线型、一次加工且无无效边时，实体记录与普通导出逐字节相同，允许的差异只有实体顺序。若新排序空走更长，回退原分组顺序；本次示例回退后与普通文件字节一致。重复线仍先阻止，必须明确选择保留，绝不静默去重。圆、底图、文字范围不变，原工程和普通导出不改。

核心 `optimizeCPPaths` 不传模式时保留旧连续 API 行为，避免破坏已有调用；用户入口 `processingOptions` 默认显式传 `independent`。连续模式允许方向变化，逐边模式在生成和回读两侧都检查源方向，修改标识不能绕过。R2000 逐边文件另命名为“R2000逐边”，避免把两点独立路径误称为已合并连续加工。

这里没有添加刀偏补偿、过切线、吸附、圆角、坐标取整、外框平移或分层自动居中。外框没有被强制移到最后。速度和压力仍只用于设置分组，必须在刻字软件中配置，程序不发送设备指令。

## 如何定位剩余实机问题

| 对照结果 | 排查范围 |
| --- | --- |
| 刻字软件导入预览已偏移 | 同源普通/优化文件的边界图层坐标、导入版本与多段线处理、分组居中或变换 |
| 预览对齐、实物偏移 | 连续外框的转向和闭环处理、加工顺序、实际工具设置及纸张固定情况；这些是待核对项，不是已确认原因 |
| 外框实际切割 | 核对纸张是否在切割后发生位移，以及用户选择的加工顺序；程序不擅自强制外框最后 |

制造商资料说明这些类别确实需要区分：[Silhouette DXF 导入支持有限](https://silhouetteamerica.freshdesk.com/support/solutions/articles/35000276938-importing-and-exporting-troubleshooting)，[Graphtec CE8000 工具转向与切割质量设置](https://www.graphtecamerica.com/s/CE8000-UsersManual.pdf)。用户设备尚未确定，不能把这些资料当作本次机器的已知配置或误差解释。
