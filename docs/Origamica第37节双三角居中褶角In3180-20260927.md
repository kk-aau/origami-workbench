# 第 37 节 In[3180] 双三角居中褶角保存例

用户给出的 `Origamica 15.0.nb` 在 234500–234566 行的 In[3180] 保存了明确输入：`ArchimedeanPatch[1]` 两个单位正三角形，`UnitRegularPolygonCenteredTwistPatch` 的 `w=0.2`、褶角 `τ=70°`，来源边赋型为 `{{M,M,M},{V,V,V}}`。In[3179] 将每片正规化后映射到 `UnitRegularPolygonCenteredTwistTile`，保留原片位置。这里的 70° 是**褶角**，不得按 In[3181] 的中心扭角 `α` 解析。保存的展示调用是双三角的 `CreasePattern` 加 `Tiling`，原笔记本没有可机读的 CP 顶点表或全局平折层序。

工作区普通阿基米德来源的 n=1 新增“**双三角居中褶角 · In[3180]**”保存预设。它固定单补片范围 `[0,0]²`、两源面、宽度、褶角和逐边 M/V；工程来源记录为 `in3180-centered-single`。普通母结构仍默认原版 2×2 样例；n=2/6/8 的现有 Alt 保存预设保持不变。来源回读逐项核验实际顶点、面、格矢、单补片范围、逐片参数、输出类型和合并选项。更改折痕参数或来源几何即清除具名来源；伪造保存例标签会被拒绝。

`scripts/verify-archimedean-patch1-centered-in3180.ts` 将工作区 JSON 预设经严格回读和通用服务构造，与绕过 JSON 分派、从原版静态接边与 `twist_patch_options(..., variant='centered', tilt=70)` 直构的结果对照。两个本项目路径的 CP 拓扑、山谷、折角、来源面索引完全一致，坐标最大差为 0；当前结果为 **20 点／30 边／11 面**，几何与局部条件通过。前端真实平折几何 `ready`，原面层序精确 1 解，正背各 261 个可见区域全部有序。采用仍由工作区实时几何和层序门禁决定；以上是原版保存公式的**本地重建**，不称 Wolfram 数值 Out 逐点等价，也不证明连续刚性折叠路径。
